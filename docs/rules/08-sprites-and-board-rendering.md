# 08 画面素材对应表：角色、建筑、图标与棋盘投影

> 适用版本：rich4.exe v3.11（与 `upstream/rich4` 一致）。
> 依据：只用逆向资料（`upstream/rich4/asm`、`csrc`、`docs`）。素材核对用 `rich4-assets/manifest.json` 与各资源的帧图（本机提取的原版素材，只读）。没有运行游戏。
> 路径缩写：`rich4.asm:N` 指 `upstream/rich4/asm/rich4.asm` 第 N 行；其它 asm 文件写文件名（省略 `rich4_` 前缀和目录）。`Data#N`、`map#N`、`Panel#N` 指 Data.mkf / map.mkf / Panel.mkf 的资源号（与 `rich4-assets/<包>/NNNN-*` 目录编号一致）。
> 表格数据（投影网格、偏移表）是从 `rich4.asm` 的 `section .data` 按标签地址逐字节还原后读出的。

可信度标签：

| 标签 | 含义 |
|---|---|
| 【代码确认】 | 在反汇编中逐行读到，附出处 |
| 【素材核对】 | 与 manifest 的帧数/锚点或帧图内容对照过 |
| 【推测·待实测】 | 由代码结构或素材内容推断，需在原版中实测 |

## 0. 结论速查

| 问题 | 结论 |
|---|---|
| 角色精灵在哪 | Data.mkf，资源号 = **128 + 角色号×21 + 槽位**（槽位 0..20，见 §1.2）【代码确认】 |
| 帧序 | **方向主序**：`帧号 = 屏幕方向 × 每方向帧数 + 动画帧`，每方向帧数 = 总帧数 / 8【代码确认】【素材核对：全部 252 个角色资源帧数都能被 8 整除】 |
| 屏幕方向 | `屏幕方向 = (玩家 +16 方向 − 视角旋转) & 7`。方向编码与 docs/rules 中 +16 的 0..7 完全一致【代码确认】 |
| 建筑帧 | 每个建筑资源 8 帧，`帧号 = (8 − 朝向 − 视角旋转) & 7`（注意符号与角色相反）【代码确认】 |
| 画面不是俯视 | 原版是**可 8 向旋转的斜 45° 正交投影**：地面先旋转 θ = −22.5° + 45°×旋转号，再缩放 1.2175 倍，竖直方向再压扁到 cos45°≈0.707【代码确认 + 数值拟合】 |
| 定位 | 精灵 = 资源帧锚点对齐到「投影后的世界坐标」，角色/建筑/图标都没有额外偏移；只有附身神明、身上炸弹有方向偏移表【代码确认】 |
| 绘制顺序 | 地面 → 事件格图标 → 涨价/查封色块 → 其它精灵按「屏幕 y×16 + 层号」排序后依次画【代码确认】 |
| 动画节奏 | 基础定时器 20 ms，每 {6,4,2} 次（游戏速度 0/1/2）出一个 tick，即 120/80/40 ms；行走、掷骰、工程车拆除都是每 tick 进 1 帧【代码确认】 |

## 1. 角色精灵

### 1.1 每个行动者的动画状态块

【代码确认】`0x498ea0 + 行动者号×0x34`（行动者 0..3 玩家、4..7 小偷/强盗/流氓/间谍、8 机器娃娃），由 `fcn_00407ad2` 在载图时清零（`csrc/loadsave.c`）。

| 偏移 | 含义 |
|---|---|
| +0 | 标志。低 4 位 = 已载入的「普通套」种类（1..4 = 交通工具+1，5 = 梦游）；位 4–5 = 已载入的「特殊套」种类（0x10 船、0x20 被击倒、0x30 病号服/囚服）；位 6 = 已做冬眠变色；位 7 = 回合待处理 |
| +1 | 当前使用哪一套：0 普通套，1 特殊套 |
| +2 | 阶段：0 静止，1 移动，2 掷骰，3 工程车拆除（同 01 文档 §1.4） |
| +3 | 动画帧计数 |
| +4 | 梦游「ZZZ」摇摆计数 0..5 |
| +5 | 落地倒计时 |
| +0x10 | map.mkf `0x1b + 角色号`（map#27..38，每个 7 帧 SMP，第 0 帧是头像，其余是小图标）。供界面用，不画在棋盘上【代码确认 loadsave.c】【素材核对】 |
| +0x14 + 阶段×8 + 套×4 | 精灵指针表：`0x498eb4` 静止·普通、`0x498eb8` 静止·特殊、`0x498ebc` 移动·普通、`0x498ec0` 移动·特殊、`0x498ec4` 掷骰·普通、`0x498ec8` 掷骰·特殊、`0x498ecc` 拆除·普通 |

画角色时取 `指针[阶段][套]`（rich4.asm:1384-1395 一带，`mov eax,[edx+0x498eb4]`）。

【代码确认】`_rich4_update_player_sprite`（rich4.asm:5297）：`B = 0x80 + 角色号 × 21`。

【素材核对】约翰乔（128..148）逐槽看过帧图：0 站立、1 走路、2 抱骰子并丢出、3–5 骑机车、6–8 开汽车、9–12 黄色推土工程车（12 为机械臂下压动作）、13–15 红白快艇、16–17 闭眼站/走（梦游）、18 帽子掉落倒地、19 白色病号服、20 黑白条纹囚服。钱夫人（191..211）对应槽位内容相同。

判定优先级（`_rich4_update_player_sprite`）：

1. `who_plays == 0` 或带 0x40 → 只载入 B+18 作为「静止·特殊」，`+1 = 1`，阶段强制 0。
2. 否则若梦游 → 普通套 = {静止 B+16, 移动 B+17, 掷骰 B+2}。
3. 否则若当前节点位 31 → 特殊套 = {静止 B+13, 移动 B+14, 掷骰 B+15}，`+1 = 1`；移动中播放音效 0xf。
4. 否则按交通工具 v（+17 低 2 位）→ 普通套 = {B+3v, B+3v+1, B+3v+2}，v = 3 时再载 B+12；`+1 = 0`；移动中切换引擎音效 0xb+v。
5. 出狱/出院时由 `fcn_0040bf93` 直接把「静止·特殊」换成 B+20/B+19 并置 `+1 = 1`，直到下一次调用 `_rich4_update_player_sprite`（回合开始、上下车、移动换节点等 24 处调用点）才恢复【代码确认】；具体能在画面上停留多久【推测·待实测】。

节点位 31 的含义：01 文档 §1.2 只记为「绘制相关」。现在可以确定它让角色换成快艇精灵，即**水路节点**（台湾 17、日本 7、恐龙 10、城市 12 个）【代码确认 + 素材核对】。

### 1.3 不在路上时不画

【代码确认】玩家循环 `loc_00408674`（rich4.asm:1303）：

- `x == 0`（未上场）不画。
- `+50..+53`（住宿/消失/坐牢/住院）任一非 0 时不画，**除非** `who_plays & 0x20`（正在走进设施）。所以原版没有「在监狱里/医院里」的棋盘精灵，囚服和病号服只在出来时出现。
- 已破产的玩家（`who_plays = 0`、坐标保留）会画成 B+18 的倒地乞丐。

## 2. 帧序、方向与动画节奏

### 2.1 帧号公式

【代码确认】玩家 rich4.asm:1418-1431，NPC rich4.asm:1584-1597：

```
fpd      = 资源帧数 >> 3
屏幕方向  = (方向(+16) + 8 − 视角旋转) & 7
帧号      = 屏幕方向 × fpd + 动画帧计数(+3)
```

- 方向编码就是 01 文档 §6.3 的 `_rich4_calculate_direction` 结果（0 下、1 右下、2 右、3 右上、4 上、5 左上、6 左、7 左下，指**世界/地图像素坐标**的方向）。
- 视角旋转 = 0 时屏幕方向 = 世界方向。【素材核对】机车 Data#131 的 8 帧依次为：车头朝屏幕下方（略偏右）、右下、右（略偏上）、右上、背面朝上、左（略偏上）、左下、左下偏下，与 §4 的投影（旋转 0 时世界 +y 投到屏幕「下偏右约 60°」、世界 +x 投到「右偏上约 16°」）一致。

### 2.2 动画计数器

| 阶段 | 帧计数怎样走 | 出处 |
|---|---|---|
| 0 静止 | 固定为 0（所有静止资源每方向 1 帧） | `_rich4_update_player_sprite` 清零 +3【代码确认】 |
| 1 移动 | 每次 `fcn_0040c05c`（每 tick 一次）+1，到 fpd 归零；与走过的距离无关 | rich4.asm:6393-6407【代码确认】 |
| 2 掷骰 | 每 tick +1；等于 fpd 时调用掷骰函数并转入阶段 1、计数清零。**掷骰动画只播一遍，不循环** | player_utils.asm:697-745（`loc_0040d975`）【代码确认】 |
| 3 拆房 | 第 0 帧时转向目标地块，在地块坐标 −55 处挂上 Data#526（`0x20e`，110×110 FLC 8 帧尘土），每 6 tick 推进一次（`0x4749e0 = 6`）；计数 = 2 时播放音效，= 3 时执行 `fcn_0040ab4a(地块, 2)` 拆房；到 fpd−1 且尘土动画放完后恢复原方向、回到阶段 0 | player_utils.asm:757-860（`loc_0040da4b`）【代码确认】 |

### 2.3 tick 时长

【代码确认】`timeSetEvent(20, 5, fcn_00401f98, 0, 周期)`（mouse_utils.asm:291-297）。`fcn_00401f98` 每被调用一次计数 +1，计数达到 `0x46cb20[游戏速度] = {6, 4, 2}` 时置 tick 标志，主循环看到标志才调用状态机 `fcn_0040d7c4`（main.asm:425-430）。

| RICH4.CFG 偏移 0 游戏速度 | tick 间隔 |
|---|---|
| 0 | 120 ms |
| 1 | 80 ms |
| 2 | 40 ms |

哪一档在界面上叫「慢/中/快」【推测·待实测：数值越大越快】。

由此：步行（8 px/tick，见 01 §6.1）在速度 0 时约 67 世界像素/秒；约翰乔走路一个循环 9 帧 = 1.08 s。

### 2.4 掷骰与骰子

1. **角色掷骰动作**（阶段 2）：骰子画在角色精灵里。【素材核对】约翰乔步行掷骰 Data#130 每方向 9 帧：第 0–5 帧双手捧骰，第 6–7 帧骰子抛出、离开身体，第 8 帧（最后一帧）骰子已不在画面中；机车/汽车/工程车掷骰（各 4 帧）在第 3 帧骰子消失。其它角色帧数不同（7–9 帧），可以认为「最后 1–2 帧骰子离手」【推测·待实测：逐角色核对】。
2. 动作放完后，`fcn_00419572`（rich4.asm:12275）先算点数，再播放**骰子翻滚动画** Panel#4/5/6（1/2/3 颗骰子各一段，189×285 FLC，36 帧），左上角 = 屏幕坐标 (136 + T.x, 48 + T.y)，T = 表 `0x475224[屏幕方向]`：

   | 屏幕方向 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
   |---|---|---|---|---|---|---|---|---|
   | T | (4,12) | (12,12) | (8,6) | (−4,−6) | (−12,−12) | (−24,−12) | (−20,−6) | (−12,6) |

   FLC 播放参数为 `{5,3,2}[游戏速度] << 4 | 1`（`0x475264`）【代码确认】；该参数是否就是每帧 tick 数【推测·待实测】。
3. 然后画点数面：Panel#3（18 帧），`帧号 = 第 i 颗 × 6 + 点数 − 1`，位置 (翻滚框左上 + (85, 145))，再按帧锚点（84, −98 等）偏移；画完停 500 ms（`fcn_0045285e(0x1f4)` 是按 timeGetTime 计时的等待，单位毫秒）【代码确认】。
4. 移动中在视图底部显示剩余步数：Data#517 第 8..17 帧是数字 0..9（帧号 = 字符 − 0x28），第一位 x = 245 − 位数×25，每位间隔 50，y = 400（屏幕坐标）；玩家在设施进出中或不在路上时不显示（rich4.asm:2666-2720）【代码确认】【素材核对】。

## 3. 棋盘上的其它精灵

### 3.1 载图时的资源表

【代码确认】`fcn_00407ad2`（load_map.asm，C 还原 `csrc/loadsave.c`）。`gmap = 关卡组×4 + 地图号`（0..7）。

### 4.2 世界 → 屏幕（原版精确算法）

数据：
- 网格表 `0x46ccf0`（rich4.asm:32468）：`int16[8 旋转][29 行][29 列][2]`，每项 `(gy, gx)`，行 = 格 y 差 + 14，列 = 格 x 差 + 14，单位屏幕像素。每个旋转 0xd24 字节（这就是 `imul 0xd24`）。
- 格内矩阵 `0x474910`（rich4.asm:40433）：`int8[8][4]`：

  | 旋转 | m0 | m1 | m2 | m3 |
  |---|---|---|---|---|
  | 0 | −34 | 11 | −14 | −25 |
  | 1 | −34 | −9 | 16 | −25 |
  | 2 | −13 | −25 | 37 | −9 |
  | 3 | 16 | −25 | 36 | 11 |
  | 4 | 37 | −9 | 16 | 26 |
  | 5 | 36 | 11 | −14 | 26 |
  | 6 | 16 | 26 | −35 | 11 |
  | 7 | −14 | 26 | −35 | −9 |

算法（`fcn_00407a2c` rich4.asm:941、`fcn_00409a23` rich4.asm:2746，以及每类对象的内联副本）：

```
frac(X, Y) = ( (m0·(X&31) >> 5) + (m2·(Y&31) >> 5),
               (m1·(X&31) >> 5) + (m3·(Y&31) >> 5) )      // 算术右移
col = (X>>5) − (CX>>5) + 14,  row = (Y>>5) − (CY>>5) + 14   // 超出 0..28 不画
屏幕x = 220 + G[r][row][col].gx + frac(CX,CY).a − frac(X,Y).a
屏幕y = 260 + G[r][row][col].gy + frac(CX,CY).b − frac(X,Y).b
```

### 4.3 等价的连续公式（重制版推荐）

把 8 张网格表做最小二乘拟合，得到一个纯仿射（正交）投影，与表的最大偏差 3.3–4.5 像素（表本身是取整生成的）【代码确认的表 + 数值拟合】：

```
dx = X − CX,  dy = Y − CY                    // 世界像素
θ  = (−22.5° + 45°·r)                        // r = 视角旋转 0..7
s  = 1.2175                                  // ≈ 38.96 / 32
k  = 0.7071                                  // cos 45°，竖向压扁
屏幕x = 220 + s·( dx·cosθ − dy·sinθ )
屏幕y = 260 + k·s·( dx·sinθ + dy·cosθ )
```

验证：旋转 0 时世界 +x 一格（32 px）→ 屏幕 (+36.1, −10.5)，世界 +y 一格 → (+14.8, +25.5)，与网格表一致。原版的地面是 2304×2304 的俯视纹理，用这个变换逐格贴图画出来（`loc_00408429` 按表 `0x473610` 的格子顺序，每格 32×32 贴到网格表给出的四边形，`fcn_004557a1`）；重制版可以整张地面一次性做同样的 2D 仿射变换。

说明：原版格内修正矩阵（m）与网格步长不完全相等（例如 |m0| = 34 而每格步长 36），所以对象跨格时会有 1–3 像素的跳动。重制版用连续公式即可，不建议复刻。

### 4.5 绘制顺序

【代码确认】`fcn_0040829d`（rich4.asm:1008-2740）：

1. 地面：按 `0x473610[旋转]` 的格子顺序逐格贴图（≤304 格，0x80 结束）。
2. 事件格图标 map#24（地面层，不排序）。
3. 收集排序列表（`0x48a84c` 每项 12 字节：精灵指针、ID、换色玩家、帧号、屏幕 x、屏幕 y）：玩家 → NPC/娃娃 → 物件 → 土地 → 设施 → 企业 → 景观。收集土地/设施时，涨价/查封色块**当场**画进地面。
4. `qsort` 按排序键的低 16 位升序（`_compare_int16_lt`），依次绘制；同键顺序不保证（qsort 不稳定）。
5. 身上炸弹的倒计时数字（随所属条目画在其后）。
6. 剩余步数大数字（Data#517）。

排序键 = `(屏幕y << 4) & 0xfff0 | 层号`：

| 层号 | 对象 |
|---|---|
| 0 | 建筑、景观、物件、所有权标记 |
| 8 | NPC / 娃娃（非当前行动者） |
| 0xc | 玩家（非当前） |
| 0xd | 当前行动者（玩家或 NPC） |
| 0xe / 0xf | 梦游 ZZZ（非当前 / 当前） |
| 键固定 0x7ff0 | 飞行中的物件 |

也就是「先按屏幕 y（锚点所在的脚底/底座）从上往下画，同一 y 时角色压在建筑上、当前行动者压在其他人上」。屏幕 y 为负或 ≥ 4096 时键会回绕【代码确认：只保留 12 位】，视图内不会出现。

  framesPerDir: number;         // 1 表示不按方向分组时也可用 frame 直接指定
  dirOrder: 'dir-major';        // frame = screenDir * framesPerDir + animFrame
  tint?: 'frozen';
}

export function characterSprite(ch: number, s: CharVisualState): SpriteRef {
  const B = CHAR_BASE + ch * CHAR_STRIDE;
  let slot: CharSlot;
  if (s.knockedDown) slot = CharSlot.knockedDown;            // 只有静止图
  else if (s.clothes && s.phase === 'idle')
    slot = s.clothes === 'prison' ? CharSlot.prisonUniform : CharSlot.hospitalGown;
  else if (s.sleepwalking)
    slot = s.phase === 'move' ? CharSlot.sleepwalkMove
         : s.phase === 'dice' ? CharSlot.walkDice : CharSlot.sleepwalkIdle;
  else if (s.onWaterNode)
    slot = s.phase === 'move' ? CharSlot.boatMove
         : s.phase === 'dice' ? CharSlot.boatDice : CharSlot.boatIdle;
  else if (s.phase === 'demolish') slot = CharSlot.engDemolish;  // 仅 vehicle 3
  else slot = (s.vehicle * 3 + (s.phase === 'move' ? 1 : s.phase === 'dice' ? 2 : 0)) as CharSlot;
  return {
    archive: 'Data', resource: B + slot, framesPerDir: CHAR_FPD[ch][slot],
    dirOrder: 'dir-major', tint: s.hibernating && s.phase === 'idle' ? 'frozen' : undefined,
  };
}

/** NPC：actor 4..7 = 小偷/强盗/流氓/间谍；8 = 机器娃娃 */
export const NPC_FPD: Record<number, number[]> = {
  4: [1, 19, 8, 17], 5: [1, 10, 9, 10], 6: [1, 15, 8, 15], 7: [1, 10, 9, 10],
};
export function npcSprite(actor: number, moving: boolean, sleepwalking: boolean, onWater: boolean): SpriteRef {
  if (actor === 8) return { archive: 'Data', resource: moving ? 522 : 521, framesPerDir: moving ? 5 : 1, dirOrder: 'dir-major' };
  const N = 0x16c + actor * 4;
  // 原版：水路节点上静止时也用水路移动图
  const k = onWater ? 2 : sleepwalking ? (moving ? 3 : 0) : (moving ? 1 : 0);
  return { archive: 'Data', resource: N + k, framesPerDir: NPC_FPD[actor][k], dirOrder: 'dir-major' };
}

export function project(x: number, y: number, camX: number, camY: number, rot: number) {
  const th = (-22.5 + 45 * rot) * Math.PI / 180, s = 1.2175, k = Math.SQRT1_2;

  };
}
