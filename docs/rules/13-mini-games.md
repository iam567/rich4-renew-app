## 1. 共同流程

### 1.1 入口（4223–4427）【代码确认】

三个入口 `_rich4_ui_game_penguin_treasure` / `_rich4_ui_game_balloon` / `_rich4_ui_game_xicongtianjiang` 开头相同：

1. 当前玩家 `+21 (who_plays) == 1` **且** `cfg+1`（动画过程）≠ 0 才玩真游戏；否则三个都跳到同一段 `loc_00415457`：
   - 分数 = `rand() % 20 + 50`；
   - `sprintf("得點券%d點")`（`ref_00463797`，Big5），讯息框 `fcn_00440cac(text, 2000)`（2 秒，点击可跳过）；
   - `_rich4_player_say(当前玩家, 0, event_strings[角色][rand() & 1])`——与 +50 点券格同两句台词。
   - 所以射气球、喜从天降的自动结算与企鹅挖宝**完全相同**（01 §7 Q7、06 §7.1 的疑问由此关闭）。
2. 真游戏：`_rich4_init_sound_effect_info(槽表)` 载入音效，`_read_mkf` 载入资源（§1.2），清空状态，`fcn_004549cf(主题)` 换音乐，`_Wait_0402_Message(窗口过程, 0)` 进入游戏自己的消息循环，结束后 `fcn_00454bcc()` 恢复背景音乐、`fcn_00454240(槽表)` 释放音效（同时停掉所有还在响的）、释放资源。
3. 返回值 = `0x48bcec`（分数）。调用处 `core_actions:2367-2383` 用 `add word [玩家+0x30], ax` 加到点券——**16 位加法，回绕**；真游戏结束后不再有讯息框或台词。

## 2. 企鹅挖宝（t=6，`fcn_00414858`，每 tick `fcn_004124c8`）

### 2.1 场地（`ref_00474d80`）【代码确认】

9×9 表，每格 8 字节 {x, y, flags, —}；x = 0 表示不能走。可走 64 格：

```
行\列 012345678
 0    ...####..
 1    .#######.
 2    .########
 3    #########
 4    ####.####     ← (4,4) 是冰屋
 5    #########
 6    ########.
 7    .#######.
 8    ..####...
```

格子中心：x = 48(列 + 行) − 64，y = 24(行 − 列) + 225（菱形，宽 96 高 48）。flags 0x10 的 5 格（行,列 = (3,3) (3,4) (3,5) (4,5) (5,5)）在冰屋后面：企鹅**当前格**是这些格时，在 (320, 225) 补画 Panel#80.3（冰屋前景）盖住企鹅。

点击图 Panel#81 是 640×480 的 8 位平面，像素值 = 行 × 9 + 列（0 = 场外）；点击时 `cell = 图[y][x]`，列 = cell % 9，行 = cell / 9。重制版用上面的菱形公式代替（与点击图逐像素比对，98% 一致，只差在菱形边线上）。【代码确认 + 比对】

### 2.2 埋宝（`fcn_00412014`）【代码确认】

种类 1..5 各埋 3 / 12 / 3 / 9 / 1 个（`ref_00411fc8`），共 28 个：每个取 `pick = rand() × 剩余格数 >> 15`，按行列顺序数到第 pick 个空的可走格。起点格 (列 2, 行 6) 也可能埋东西。

| 种类 | 是什么 | 地图图标 | 出土动画 | 分数 | 音效 |
|---|---|---|---|---|---|
| 1 | 炸弹 | #80.4 | #86（爆炸） | 游戏结束 | #15 |
| 2 | 金币 | #80.5 | #87 | 5 | #16 |
| 3 | 红宝石 | #80.6 | #88 | 12 | #17 |
| 4 | 蓝宝石 | #80.7 | #89 | 8 | #17 |
| 5 | 钻石 | #80.8 | #90 | 20 | #18 |

分数 = 5·金币 + 12·红 + 8·蓝 + 20·钻石，理论最高 188。（音效表 `ref_00475051`。）

### 2.3 输入（WM_LBUTTONDOWN 0x201 / 双击 0x203）【代码确认】

- 结束显示中：点击 → 结束显示。
- 只有企鹅闲着（`0x48bccc == 0`）、未结束、开场计数为 0 时才接受；点到场外、不可走的格、或企鹅自己站的格都无效。
- 有效：设定直线路径（§2.4），状态 = 走路，**循环**播放 #11（脚步）。走路、挖掘期间点击无效，不能中途改目标。
- 时间不会因为点击而暂停；企鹅走一格 4 tick（0.4 s），挖一次 4 tick。

### 2.4 走路（`fcn_0041211c` 定向，`fcn_00412287` 下一格）【代码确认 + 穷举】

- 定向：位置小数部分清零再 +0.5（16.16 定点），dx = 目标列 − 当前列，dy = 目标行 − 当前行；沿较长轴每步 1 格，另一轴每步 `(d << 16) / |长轴|`（截断）。
- 下一格 = 位置 + 步长。若那格不可走（冰屋、场边）：长轴照走一格，另一轴若本来不换行/列就**侧移一整格**（方向取步长符号，步长 0 时取 +），否则这一步不动另一轴；记「绕行」标志，到达后从新位置重新定向。
- 每到一格：若是目标 → 停 #11、播 #12（挖），进入挖掘；否则（绕行过就先重新定向）取下一格。
- 朝向（每格开始时算，dc/dr = 下一格 − 当前格）：dc > 0 → 3 − dr；dc = 0 → dr > 0 ? 1 : 5；dc < 0 → (dr + 7) & 7。0 下、1 右下、2 右、3 右上、4 上、5 左上、6 左、7 左下（与棋盘的 8 方向相同）。
- 画：Panel#82 第 朝向×4 + 步 帧，位置 = 当前格中心 + ((下一格 − 当前格) >> 2) × 步。
- 重制版穷举了 64 × 63 种起点/目标组合：原版算法全部能到达，最长 32 tick，绕行 470 次，**从没走出场地**。重制版仍保留一个保险（侧移落在不可走格时改走离目标最近的可走邻格），实际不会触发。【代码确认 + 穷举】

### 2.5 挖掘与出土【代码确认】

- Panel#83 第 朝向×4 + 步 帧，4 tick。第 3 tick（步 2）把洞 Panel#80.9 **画进背景**（之后一直在）；第 4 tick（步 3）看格子下面：有东西就从格子上拿走，开始出土动画。
- 出土动画：Panel#(85 + 种类) 第 0–5 帧，每 tick 一帧，画在格子中心（这几帧的锚点在图下方 44–75 px，所以宝物从洞里升起；炸弹的 #86 是爆炸）。
- 挖完：空 → 闲着；炸弹 → 状态 1，播 #15；其它 → 闲着，播该种类音效，计数 +1，刷新数字条。

### 2.6 结束【代码确认】

- **炸弹**（状态 1）：前 3 tick 站姿 #80.1，之后惊吓 #80.2，第 15 tick 结束。第 4 tick 起大分数画进背景。
- **时间到**（剩余 tick 减到 0）：停 #11；分数 < 40 → 沮丧（状态 5，Panel#85 6 帧 × 4 遍，循环播 #14），> 55 → 高兴（状态 4，Panel#84 8 帧 × 4 遍，循环播 #13），其余 → 原地站 15 tick（状态 6）。动画播完停掉对应音效后结束。大分数从动画开始就显示。
- 时间到时企鹅正在走或挖，也立即换成结束动画（挖到一半的东西不算）。炸弹的惊吓期间时间照走，若此时时间到，同样换成结束动画。
- 然后 §1.5：20 tick 大分数，点击可提前结束。

## 3. 射气球（t=7，`fcn_00414bbc`，每 tick `fcn_00412f6f`）

### 3.1 每 tick【代码确认】

顺序：冻结计数 `0x48bd59` 减 1 → 剩余 tick 减 1（到 0 时进入「结束中」）→ 刷新时钟 → 更新气球。

16 个槽（`0x48bc44`，每槽 {x, y, 种类 | 爆裂计数<<4}）：

- 有气球：爆裂中则计数减 1，到 0 移除；否则（未冻结时）y −= 速度。速度按种类（`ref_00475004`）：0–3 为 15，4–6 为 18，7 为 24，8–10 为 24，11 为 18；加速时 ×2，减速时 >>1。画 Panel#91 第 种类+1 帧（爆裂中第 13 帧），只画在上方 640×387 的区域里；整个帧都在区域外（飞出顶端）就移除。
- 空槽且未结束：`r = rand() % 1000`：
  - r < 20：种类 r >> 2（0..4，大气球）；
  - 20 ≤ r < 28：种类 (27 − r) >> 1 + 5（5..8；6..8 是小气球）；
  - r = 28、29：特殊，`ref_00475039[rand() % 10]` = {9,9,10,10,10,10,10,11,11,11}：×2 占 20%，÷2 占 50%，「?」占 30%；
  - 其余没有。
  - 有新气球时，在 8 列 x = 40 + 80n 中挑**底部空着**的列（该列没有 y > 300 的气球），`rand() % 空列数` 选一列，从 y = 420 升起，播 #19。
- 「结束中」且场上没有气球 → 结束（§1.5）。

每 tick 每个空槽约 3% 出气球，16 个槽都空时约 39%。

### 3.2 点击（0x201 / 0x203）【代码确认】

只在 READY GO 之后、未进入大分数时接受——**时间到之后，剩下还在飘的气球照样可以射**。对每个没在爆裂的气球判定：种类 ≥ 6（小气球和特殊）框 ±18 × ±26，其余 ±22 × ±30（以锚点为中心，含边界）。一次点击可以打破重叠的几个。

> **重制版改动（手机触控）**：
> 1. 高清气球的身体比原版判定框更长（下半截收窄的部分到锚点下方约 +44/+50），判定框下边因此加长 18，看得到的气球身体都能点中。
> 2. 手指点击（非鼠标）时，如果没有正好点在气球身上，就打破离手指最近、且在约 16 个 CSS 像素范围内的**一个**气球（不会连带打破旁边那一列）。鼠标仍照原版判定。

| 种类 | 帧 | 效果 |
|---|---|---|
| 0–8 | 1–9 | 分数 + 种类 + 1，上限 999 |
| 9 | 10 | 分数 ×2（**不设上限**） |
| 10 | 11 | 分数 >> 1 |
| 11「?」 | 12 | 先清掉冻结与变速，再 `rand() % 6`：0 时间 = 1（下一 tick 时间到）；1 冻结 20 tick；2 速度 ×2；3 速度 ÷2；4 分数 = 0；5 分数 ×2 |

打中的气球爆裂计数 = 3（画 2 tick 第 13 帧后移除），播 #21；没打中的每个气球都播一次 #20（同一槽重播，听起来一次）。

### 4.3 玩家角色与接物【代码确认】

- 角色 Panel#(100 + 角色)：前 5 帧是姿势，然后左走、右走各 n 帧（n = (帧数 − 5) >> 1，12 名角色 10–14 帧）。站在 y = 380，起点 x = 320。
- 每 tick：目标 = 光标 x，距离 > 8 就朝目标走 10 px（方向 1 左 / 2 右，走路帧前进一格）；距离 ≤ 8 时**不动，但方向保持**，画面停在当前走路帧。
- 接物：方向 ≠ 0 时才判定。原版只有开局还没动过、以及被炸之后方向是 0，所以**「只有移动中才能接」并不准确：动过一次之后站着也能接**（06 §7.2 原写法据此修正）。判定框 = 当前帧的矩形（x − 锚点x … + 宽，380 − 锚点y … + 高），物体的 (漂移后 x, y) 严格在框内即接到；同一 tick 物体先判定、角色后移动。
- 接到炸弹：停 #24，播 #15，Data#526 爆炸画在左上角 (x − 55, 295)（110×110，flags 1 叠画，`fcn_00450ced`），方向 = 0，姿势 = 4（受伤），进入结束中，之后不再移动、不再接物；爆炸每 tick 一帧（`fcn_00450f04` 每次调用前进一帧，8 帧 = 0.4 s），播完进入结束。
- 结束时姿势：没被炸则分数 < 40 → 1，< 50 → 2，< 60 → 0，否则 3；重画一次，大分数 2 s。

### 4.4 原版的鼠标控制【代码确认】

`fcn_00413248` 每 tick `GetCursorPos`，与上次记下的 x（`0x47504f`）比较：向左移动超过 8 px 就 `SetCursorPos(0, y)` 并记 0，向右超过 8 px 就 `SetCursorPos(639, y)` 并记 639。所以鼠标一甩，光标被拉到屏幕边上，角色一路跑到墙边；只有 8 px 以内的慢动作才精确跟随。没有键盘控制。

【重制取舍】触屏没有「甩」这个动作，光标拉到边也不适合浏览器：重制版直接跟随指针 x（鼠标移动、手指按住拖曳），另加 ← → / A D 键按住时跑向该侧、放开即停。其余（10 px/tick、8 px 死区、方向保持）照原版。

## 5. 重制实现说明

- 入口：`Places.miniGame(p, kind)`：`g.isHuman(p) && g.animation` 时问界面 `{ t: 'mini-game', p, game: kind }`，回答 = 分数（非正数或无回答当 0），`(点券 + 分数) & 0xffff`；否则 `rand() % 20 + 50`，先发 fx `mini-game`（data.points），由地图导演显示「得點券N點」2 s 和 0/1 号台词。两种情况最后都发 `points` 事件。
- 「动画过程」：重制版没有其它地方用到这个开关，设置里只叫「小游戏：亲自玩 / 自动结算」（localStorage `rich4.minigame`，不进存档）。
- 小游戏自己的随机数用界面的 `Math.random`（模拟 libc 的 0..32767），不消耗规则引擎的随机数，存档复现不受影响。
- 时间按真实毫秒（100 / 50 ms），与游戏速度设置无关（原版 SetTimer 也不看速度）。
- 光标：企鹅、气球在画布上画 Data#0 的原版光标（隐藏系统光标），只对鼠标；触屏不画。
- 竖屏：640×480 画面下方加一块说明（标题、玩法、分数表）；横屏开场时在顶部空白处显示同样说明，GO 之后淡出。原版没有这些说明。【重制取舍】
- 结束时在大分数下方加一行「得點券 N 點」。【重制取舍】
- 调试：`window.__rich4.askScreens['mini-game'](window.__rich4.ctx(), { t: 'mini-game', p: 0, game: 6 })` 直接打开，`window.__rich4Mini` 是正在玩的游戏状态。
