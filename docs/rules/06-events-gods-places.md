| +0x48 (72) | **运势值** luck_fate（i16） |

- **天数字节的高位**：+50..+53 这类天数字节的 bit7（0x80）表示“计数已到 0，下次处理时释放”，详见 §9.3。【代码确认】`rich4_player_core_actions.asm:4101-4196`（fcn_0041c84f）
- **随机数**：`_libc_rand()` 返回 0..32767，代码一律用 `rand() % n` 或 `rand() & 1`。每天日结时会用 `GetTickCount` 重新 `srand`（`rich4_player_core_actions.asm:4834-4836`），所以原版的随机序列不可复现。重制版只需在分布上一致。【代码确认】
- **转账** `fcn_0041d2c6(付款方, 收款方, 金额, flag)`（`rich4_player_core_actions.asm:5058`）【代码确认】：
  - 付款方 ≥100 表示地图上的上市企业（编号 = 付款方 −100）。
  - flag bit2=1 时先扣存款再扣现金，否则先扣现金再扣存款。两者都不够就扣到 0，并调用 `_rich4_player_bankrupt`。
  - 收款方 −1 表示系统，钱累加进 `0x499080`，也就是乐透奖池（§8）。
  - 收款方是玩家时，flag bit0=1 进现金，否则进存款。
- **加钱** `fcn_0041d3f4(玩家, 金额, flag)`：flag bit0=1 加到现金，否则加到存款。【代码确认】`rich4_player_core_actions.asm:5173`

## 2. 共用判定机制

### 2.1 神明好运/霉运判定 `fcn_0044b896(kind, sub)`

【代码确认】`rich4.asm:22733-22897`。这是命运事件里**唯一**的神明判定入口。新闻、魔法屋、小游戏、乐透都不调用它。

调用前先根据当前玩家的 luck 值得到一个结果 r，含义随调用参数不同：

| 调用 | 用哪个值 v | v>100 | 50<v≤100 | 0≤v≤50 | v<0 |
|---|---|---|---|---|---|
| (0,0) 金钱**收益** | luck_money(+70) | r=2：奖金加倍 | `rand()&1` 为 1 时 r=2，否则 0（50% 加倍） | r=0 | r=1：**奖金作废** |
| (0,1) 金钱**损失** | luck_money(+70) | r=1：免付 | `rand()&1`：50% r=1 免付，否则 0 | r=0 | r=2：**罚金加倍** |
| (1,x) **厄运**（非金钱） | luck_fate(+72) | r=1：逃过此劫 | 50% r=1，否则 0 | r=0 | r=2：**倒霉加倍** |

- r≠0 时会生成提示文字，例如“某神保佑 免付罚金”，神名取自 `god_names[god_info−1]`。各事件拿到 r 之后怎么处理，见命运各条目。
- **注意**：有几个事件拿到 r=2 后**没有**加倍分支，等于 r=2 被忽略（见 §3.3 的标注）。

luck 值的来源是附身神明（§5.1 的数值表）。附身时加，离开时减，所以同一时刻只反映一个神。

### 2.2 免罪卡与嫁祸卡 `_rich4_try_mianzui_jiahuo_card(p)`

【代码确认】`rich4_card_utils.asm:17-60`

1. p 持有免罪卡（卡 ID 21）时**自动使用**，返回 −1，事件整体取消。
2. 否则若持有嫁祸卡（卡 ID 19），尝试使用：返回被嫁祸者，事件改由他承受。人类会被询问，电脑按自己的逻辑决定（卡片文档负责）。
3. 两种卡都没有就返回 p 本人。

这一步只出现在“入狱、住院、出国或被外星人绑架”类命运、魔法屋 2/10 号、新闻 #29 中。**神明判定在前，免罪/嫁祸在后**：先算 r，r=1 直接结束；r=2 先把天数加倍，再问卡片。

### 2.3 保险理赔 `fcn_0044ba63(p, 金额, _)`

【代码确认】`rich4.asm:22899-22946`

- 条件：p 的保险天数（+62）≠0。
- 理赔方：地图上第一个类型字节（+0x1a）等于 4 的上市企业，也就是保险公司。
- 赔付：`fcn_0041d2c6(100+企业号, p, 金额, 1)`，钱进现金，并提示“保险期间得到理赔金”。
- 调用点和金额：

| 情形 | 理赔金额 | 出处 |
|---|---|---|
| 住院 | 天数×2000×F | `rich4_hospital_utils.asm` |
| 坐牢 | 天数×2000×F | `rich4_prison_utils.asm` |
| 出国或被外星人绑架 | 天数×2000×F | `rich4_player_utils.asm:189` fcn_0040d375 |
| 命运中付给系统的罚款 | 全额（**等于罚款白付**） | `rich4_fortune.asm` loc_0044cec2 |
| 命运“冒贷” | 冒贷金额 | fcn_0044c0e8 |

- 保险天数每日递减，到 0 时置 0x80，下次处理时清零（core:4332、4457-4466）。所以到期当天仍然算有保险。【推测·待实测】

### 2.4 入院、入狱、消失的写入方式

- `_rich4_add_player_days_in_hospital(p, d)` 和 `_rich4_add_player_days_in_prison(p, d)`（两者结构完全相同）：
  - **已在院或已在狱**：天数 = (原值 + d) & 0x7f，**叠加**，并清掉 0x80 待释放位。
  - **否则**：先清掉其他状态（fcn_0040d761），清 who_plays 的高 4 位，把玩家传送到医院或监狱节点，天数设为 d。
  - **两种情况都会**：说一句台词，按 §2.3 理赔，累计缺席天数（+66）加 d。
  - 【代码确认】`rich4_hospital_utils.asm:30-168`、`rich4_prison_utils.asm:30-168`
- 出国或被外星人绑架 `fcn_0040d375(p, d, type)`：写消失天数（+51）。type 0 表示出国，type 1 表示外星人，写在 bit6。已在消失中时天数叠加。其余同上（理赔、+66 加 d、移出地图）。【代码确认】`rich4_player_utils.asm:189-260`
- 受伤丢车 `fcn_0040cd07(p)`：p 若骑机车或开汽车，车退回商店库存，p 改为步行，骰子数设为 1，打上 0x40 标记。命运中“掉水沟”“机车摔伤”在入院前都会先调用它。【代码确认】`rich4.asm:6887-6935`

### 3.2 抽牌机制：固定的循环牌堆

【代码确认】

- **建牌**：`fcn_0044baea`（`rich4.asm:22948-22999`）**只在新开局时调用一次**（`rich4_new_game.asm:4285`）。它把 0..36 共 37 个牌位均匀洗成一个排列，写入 `0x496b38[37]`，并把指针 `0x4990b4` 设为 0。
  - 洗法：第 k 步取 `rand() % (37−k)`，选第 r 个尚未使用的编号，等价于 Fisher–Yates。
- **抽牌**：`fcn_0044db81`（`rich4_fortune.asm:2529`）。
  1. 取 `t = deck[ptr]`，执行前置检查 `fcn_0044bb4b(&t)`。检查可能改写 t，比如把 10 改成 11，用来按交通工具换成对应事件。
  2. 不论检查是否通过，ptr 都加 1，到 37 回到 0。
  3. **不满足条件的牌被跳过并消耗掉**，循环直到抽到一张满足条件的牌。
- **执行**：
  - t<33 时，调用 `call_table[t]`。
  - t≥33 时，调用 `call_table[game_map×4 + t]`，`game_map` 在 0x4991b8。
  - 阶段 0 画面板文字（第一次调用回调，参数 0）；等 1600ms 后执行效果（第二次调用，参数 1）；再等 800ms。
- **永不重洗**：同一局里 37 张牌永远按同一顺序循环。牌堆和指针都写进存档（`rich4_player_save_state.asm:360-370`），**读档后命运顺序不变**。
- **概率含义**：命运不是每次独立随机，而是一个固定的周期序列。
  - 平均来看，每个牌位每 37 次被经过 1 次。
  - 某条事件实际出现的频率取决于前置条件。在 game_stage≠0 的地图上，33..36 永远被跳过，有效牌只有 33 张。
- 命运触发入口只有两处：停在命运格（§1），以及魔法屋 1 号“抽取命运三张”（§6）。

### 5.2 出现、附身与覆盖

【代码确认】

- **开局**：清空对象表后，把类型 1、3、5、7、9、11（小财神、小福神、小穷神、小衰神、天使、恶犬）和 13（礼物）、14（宝箱）各放到一个随机节点。（`rich4_load_map.asm:257-306`）

  - 每个日结处理该玩家时减 1，到 0 就离开。（core:4468-4480）

  1. 从玩家身上减去 luck 值，god_info 清零；
  2. 若离开的是穷神、衰神、恶魔或死神（类型 5..8、15），说一句台词；
  3. 若玩家当时在旅馆、消失、坐牢或住院中，静默移除，不播动画。

【代码确认】`rich4.asm:19522-19950`（`fcn_0043f23e`，跳转表 `ref_0043f21a`）、`rich4.asm:21169-21330`（`fcn_00440706`）、`rich4.asm:19257-19425`（`fcn_0043ef3e` 转轮）、数据 `rich4.asm:41240-41290`、`rich4_gods.asm:555-942`。

- 读 Panel.mkf 第 0x43 = **Panel#67**（SMP 24 帧）；保存 (0,40)–(440,480) 背景（`fcn_00451e7e`），结束时还原。
- 讯息框 Data#517.5 画在 (220,140)，文字 `fcn_00440706` 跳转表 `ref_004406ee`：`"%s附身\n\n向所有對手收..."`（小財神）、`"…送您..."`（大財神）、`"…付給每個人..."`（小窮神）、`"…損失..."`（大窮神），%s = 神名；字体 16 px、#f0f0f0、描边 #101010。

- 转轮条：#67.4..23 是位置 0..19（38×36）；**位置 2k = 数字 k 居中，奇数 = 两个数字之间**。x = `ref_00475ce8[m][i]`：四轮 145/182/219/256，三轮（第 0 轮不画）163/200/237；y = 320。
- 结果：讯息框重画，只写 `"%d元"`（`ref_00465284`），停 40 帧后关闭（不等点击）。

**循环**（每帧至少 30 ms，`timeGetTime`；状态 esi）
| 状态 | 每帧做什么 |
|---|---|
| 1 转动 | 帧计数 %10 == 0 时 4 个位置都 = `rand()%10*2+1`（**每次 4 个 rand()，三轮机也调 4 次**）；每帧每个转轮 +1（到 20 归 0） |
| 2 拉杆 | 照转一帧；画 #67.3；播 UI[1]（Effect#1）；计数归 0 → 3。从这里起不再调 rand() |
| 3 | 照转；第 4 帧画回 #67.2 → 4 |
| 4..7 | 从右往左逐个停：`fcn_0043ef3e(m, 掩码, k)` 停第 4−k 轮。该轮位置为奇数的那一帧开始减速（计数 0x475d5c/5d）：分别隔 1、2…7 帧再走一格，共 7 格，停在偶数位置（数字居中）；`0x475d5c` 到 8 时返回 1 → 下一轮。已停的轮不再画。三轮机 6 → 8（跳过第 0 轮） |
| 8 | 停 Effect#51（`fcn_004542e9(0x475d3c)`），算金额、画 `"%d元"`；计数归 0 |
| 9 | 计数到 40 → 10，结束 |

- **金额** = 第 1 轮×100 + 第 2 轮×10 + 第 3 轮（数字 = 位置>>1）；四轮机（参数为奇数，即大財神、大窮神）再加第 0 轮×1000。**不乘 F**。
- **谁停**：状态 1 时收到 WM_LBUTTONUP / WM_RBUTTONUP / WM_KEYUP（**画面任何位置点击、右键或放开任何键**），且**当前玩家**（`_rich4_current_player`，不是附身者）+21 == 1（人类、未托管）并且 +55 == 0（未梦游）→ 状态 2。否则（电脑、托管、梦游）在帧计数到 40 时自动进入状态 2（即第 39 帧，约 1.2 秒）。拉杆之后的点击没有作用。
- **随机数**：拉杆所在帧号 S（人类 = 点击后的下一帧，≥1；电脑 = 39）决定调用次数 = 4 × (⌊S/10⌋ + 1)：电脑恒为 16 次。拉杆之后完全确定：例如电脑的个位数字 = （第 30 帧那次 rand()%10）+ 1（模 10）。
- 时长：电脑约 40 + 4 + 每轮约 30 帧 ×3 或 ×4 + 40 帧 ≈ 5.2 s（三轮）/ 6.1 s（四轮）。
- 声音：开始时循环 Effect#51（槽表 `0x475d3c`，`fcn_00440706` 和 `fcn_0043f23e` 开头各播一次 flags 1），拉杆 UI[1]，状态 8 停。
- 静态变量 0x475d5c/5d 每轮停完归 0；0x475d5e（正在停的轮号）跨次保留，但每次从 k=1 开始而它只会是 0、3、4，不影响结果。
- 【推测·待实测】点击是用 `PeekMessage(PM_REMOVE)` 取的，进入拉霸前**还在队列里的按键/鼠标放开**也可能在第 1 帧就拉杆；金额分布均匀（模拟 5000 次每位数字约 10%）。

**重制版**：`game/src/core/modules/slot-machine.ts` 逐帧重放上面的循环（rand() 次数与原版相同），`objects.ts` 对人类发 `slot-machine` 询问（回答拉杆帧号），电脑/托管/梦游用 39；画面 `game/src/ui/screens/slot-machine.ts`（点画面任何位置或放开任何键拉杆；电脑的拉霸点一下直接看结果——这一点是重制版的方便，原版不能跳过）。

### 9.3 每回合扣减与释放

对旅馆、消失、坐牢、住院四个字节依次处理：

```
若 v & 0x80 → 执行释放（release_from_prison / hospital 等）；本字节此时仍是 0x80，走出门时才清零（§9.3.1）
```

- 同一次处理中，如果 4 个状态全为 0（dword +50 = 0），再处理冬眠和梦游。

  - 回合内的顺序是“先释放、走出门、再照常行动”，见 §9.3.1。【代码确认】

#### 9.3.1 出院、出狱：先走到门口那一格并判定

【代码确认】玩家 0..3（GitHub issue #2，2026-10-22 起重制版照此实现）。

## 11. 重制实现要点

### 11.1 必须还原的行为

1. **命运和新闻都是“开局洗一次、永久循环”的牌堆**，指针写入存档，跳过的牌也会消耗。不要实现成每次独立随机。
2. **神明判定是阈值三档加 50% 抛币**，只作用于命运；损失类判定之后还要叠加保险理赔。
3. **神明成对轮换**，场上每一对恰好存在一个；礼物和宝箱每月 1 日重放。
4. 罚款进奖池；乐透每月 15 日开奖；奖池和乐透门票价格不乘 F。
5. 入院或入狱 d 天 = 跳过 d 个自己的回合；天数叠加；期间不收过路费。
6. 拉霸金额（§5.7）、乐透门票、小游戏点数、新闻 #11 与 #23 **不乘 F**；其余大部分金额乘 F（见各表）。

### 11.2 类型草案（TypeScript）

```ts
    deck.ptr = (deck.ptr + 1) % deck.order.length;
```
