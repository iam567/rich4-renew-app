> 依据：`upstream/rich4/` 下的反汇编（asm/）、C 还原（csrc/、asm/*.c）、文档（docs/）；原版存档 `~/Downloads/Rich4add/Save0.dat`、`SAVE1.DAT` 与 `RICH4.CFG`（只读解析）。随机数和配置读取两处 C 运行库代码没有包含在 asm 中，因此直接读取了同目录原版 `rich4.exe` 中对应地址的机器码（只读）。

  - +0x16/+0x17/+0x19/+0x1a 的含义来自托管 AI 设置界面的文字标签：`使用卡片`、`使用道具`、个性三档 `乖宝宝/普通人/大老奸`、“资金运用比例”两行 `现金|存款` 与 `股票|资金`【代码确认 asm/rich4_ui_ai_settings.asm，字符串 ref_00463cd8…ref_00463d33，回写在 loc_0041e23e 一段把临时值写回 +21/+22/+23/+25/+26】。
  - +0x18 不在设置界面中出现；唯一的读取点是银行的 AI 自动贷款，按它乘以“可贷额度”/100 计算贷款额，因此本文称为“贷款比例”【代码确认 asm/rich4_ui_bank.asm:3662-3672】。

## 3. AI 总体框架

### 3.1 AI 的判定与设置

- 一个玩家是否由 AI 操作：`control & 6 != 0`（bit1=电脑，bit2=托管）【代码确认 rich4_player_core_actions.asm:410、1010、1660】。`control == 1` 表示纯人类，会弹确认框（`fcn_00440ba8`）。
- 托管 AI 设置界面（`_rich4_ui_ai_settings_entry`，asm/rich4_ui_ai_settings.asm:842）只列出 `control & 1` 的玩家（人类），可以修改：托管开关（control bit2）、使用卡片/道具（aiFlags bit0/bit1）、个性（0/1/2）、现金|存款比例与股票|资金比例（0–100，每次 ±10）【代码确认 同文件 loc_0041e15a–loc_0041e228】。电脑玩家的这些参数固定取自角色档案。
- 没有全局“难度”选项；AI 强弱由每个玩家的个性和比例参数决定【推测·待实测：在新游戏设置中未找到难度变量】。

### 3.2 AI 回合流程

`fcn_00418c55` 按行动者类型走跳转表：人类走界面；电脑/托管走 loc_00418dc6【代码确认 asm/rich4.asm fcn_00418c55 起约 124-185 行】：

1. 若是特殊角色（号 ≥4）或 control 带 bit4/bit5（正在进出建筑），直接结束回合。
2. 买股票 `fcn_0042bf03` → 卖股票 `fcn_0042c79f` → 处理特别融资 `fcn_00436b0a`。
3. 若游戏已结束（0x46caf8 ≠ 0）退出；否则进入交易所 `_rich4_ui_sale_entry`（AI 挂牌/收购）。
4. `rand() & 1`：为 1 尝试用卡（`_rich4_ui_use_card_entry`），为 0 尝试用道具（`_rich4_ui_use_tool_entry`）——**每回合只会尝试其中一种**。
5. 若住旅馆/消失/坐牢/住院（+0x32 起 4 字节任一非 0）、梦游或冬眠，结束；否则掷骰前进（`fcn_004221c0`），回合结束 `fcn_0040dd1f`。

### 3.3 各决策点

#### (1) 买空地
- 入口：`_rich4_handle_player_land_on_node`（asm/rich4_player_core_actions.asm:322），空地分支 loc_0041a013。
- 先决条件（人和 AI 相同）：不在梦游；附身的不是 12 号（土地公）；价格 ≤ 现金。价格 = (地块 +0x1e × 当前等级 + 地块 +0x1c) × PI【代码确认 同文件约 1000-1010 行】。
- AI 判断 `fcn_0041d7d4`（同文件:5542）：
  `保底 = min(trunc(初始资金 × 0.05), 7000) × PI`；**现金 + 存款 − 价格 > 保底** 时买，否则不买。没有随机，不看个性【代码确认】。
- 购买设施类地块：价格 = 记录 +0x22 × PI，AI 用同一个 `fcn_0041d7d4` 判断【代码确认 同文件约 1650-1665 行】。

#### (2) 加盖、建设施、升级设施
- 自己的地加盖：条件为等级 <5、不是连锁店（地块 +0x18 = 0）、不在梦游、加盖费 = 地块 +0x1e × PI ≤ 现金【代码确认 同文件:370-395】。
- AI **不做储备金判断、没有随机，条件满足就加盖**；只有附身对象为 7（小衰神）、8（大衰神）或 15（死神）时被 `fcn_0040fa61` 拦下【代码确认 同文件:410-420；asm/rich4.asm:6970】。
- 加盖花费累加到地块 +0x2c（累计投入）【代码确认 同文件约 976 行】。
- 建设施时 AI 用 `rand() % 4 + 1` 随机选设施类型；设施升级上限按类型 1–4 为 5、5、1、5【代码确认*】。

#### (3) 按数量购买
- `_rich4_calculate_max_purchase_count`（同文件:5575）：`可用 = 现金 − trunc(初始资金 × 0.3) × PI`；≤0 买 0；够买满上限就买满，否则买 `可用 / 单价` 份【代码确认】。调用点在 `fcn_0041d1a9`（日结算中处理地块租期的部分），人类在这里弹窗确认【代码确认 同文件:4985-5020】，与土地权限选项 0x499110 相关【推测·待实测】。

#### (4) 银行：存取款
- `_rich4_ui_bank_atm_entry`（asm/rich4_ui_bank.asm:5054）中的 AI 分支（约 5130-5205 行）【代码确认】：
  1. 总额 = 现金 + 存款；当前比例 = 现金 / 总额。
  2. 目标比例 = aiCashPct / 100.0；当天日期 ≤7 号时 ×1.5；≥26 号时 ×0.5。
  3. 目标 ≥1.0 时改为 0.9；目标 ≤0 时改为 0.1。
  4. 差 = 当前比例 − 目标；若 −0.25 < 差 < 0.25 且现金不为 0，不动；否则调整为：现金 = trunc(总额 × 目标)，存款 = 总额 − 现金。

#### (5) 银行：借款与还款
- 入口 `_rich4_ui_bank_entry`（asm/rich4_ui_bank.asm:3490）。拒绝往来天数（+0x3b）非 0 时直接离开；可贷额度 = `_rich4_calculate_player_wealth(玩家)`，存于 0x48c3b0【代码确认】。
- AI 分支（control ≠ 1）先看是否已有贷款：
  - **已有贷款 → 考虑还款**（loc_004367ab）：“到期在即且还得起” = 距到期日（+0x2c）≤6 天，且 现金+存款 ≥ 贷款 × 1.1。若 贷款 × 2 < 存款，或“到期在即且还得起”成立，则还款（`fcn_00433bd8`）；否则不动【代码确认 同文件:3582-3610，常数 1.1 在 ref_00464b24】。
  - **没有贷款 → 考虑借款**（loc_00436893）：先掷 `rand() % 10`，为 0（10%）时不看资金，否则要求 现金 + 存款 < 30000。然后要求停贷天数（+0x3c）= 0 且 aiLoanPct ≠ 0。贷款额 = aiLoanPct × 可贷额度 / 100（整数除），记入 loan 并加到存款，到期日设为今天 + 90 天【代码确认 同文件:3644-3675，193-206】。
- 特别融资：AI 每回合在股票操作之后调用 `fcn_00436b0a(0)` 强制偿还【代码确认 调用位置】【代码确认* 强制偿还的含义】。

#### (6) 股票
- 买入 `fcn_0042bf03`（asm/rich4.asm:14733）【代码确认 1–4 步】：
  1. `rand() % 3 != 0` 则跳过（2/3 概率不操作）。
  2. aiStockPct = 0 跳过；`fcn_00428d01` 返回 1（休市）跳过；有贷款到期日且距到期不足 15 天跳过。
  3. 持股市值 = Σ 股数 × 当前价（股票记录 +20 的 float）。
  4. 目标 = (存款 + 现金 + 持股市值) × aiStockPct / 100；持股市值 ≥ 目标则不买。
  5. 可用资金 = min(目标 − 持股市值, 存款)；按“是否关联自己的设施”和“相对历史均价”给 12 支股票打分，降序排序；第 i 名以 `rand() % 24 <= 12 − i` 的概率被选中，买入数量 trunc(可用 / 股价)【代码确认*】。

## 4. 随机数生成器

### 4.1 算法【代码确认】

游戏使用 C 运行库的 `rand/srand`（rich4.exe 中 `rand` 位于 0x456f2d，`srand` 位于 0x456f50；asm 里以 `_libc_rand/_libc_srand` 外部符号出现，upstream 重编译时被换成 MSVCRT，见 `asm/mscrt.ld:15-16`）。读取原版 exe 机器码得到：

```
state = state * 1103515245 + 12345        (按 uint32 取模)
rand() = (state >> 16) & 0x7FFF           (0..32767)
srand(seed): state = seed                 (完整 32 位)
```

- 状态保存在 CRT 线程上下文（`0x456f23` 的取址函数返回 `ctx + 0xC`）；取址失败时 `rand` 返回 0（实际不会发生）。
- 未调用 srand 时的初值没有在机器码中看到；游戏启动时一定先 `srand`，所以初值对行为无影响。
- 重制时必须使用上述 LCG，不能用宿主语言的随机数（MSVCRT 的常数不同）。

### 4.2 播种位置【代码确认】

| 位置 | 种子 |
|---|---|
| 启动 `_rich4_initialize`（asm/rich4_initialize.asm:146） | `GetTickCount()` |
| 每天日结算 `fcn_0041cf67`（asm/rich4_player_core_actions.asm:4830），在股票日更新 `fcn_004291d6`、节日处理 `fcn_00452444` 之前 | `GetTickCount()` |

原版每天都用时间重新播种，存档中不保存随机状态，**整局无法仅凭存档复现**。重制版应每局持有一个生成器实例，并在同样三个时机用可记录的种子重播种，便于回放和测试。

### 4.3 使用方式

- asm 中共 182 处 `call _libc_rand`，另有 C 还原 `rich4_tool_utils.c` 中领取随机道具 1 处【代码确认 grep 计数】。
- 常见取法：`rand() % n`（有符号 idiv，rand 非负，等价于普通取模）、`rand() & 1`、`rand()/32767.0`、`rand()/65536.0`。
- 掷骰子 `fcn_00419572`（asm/rich4.asm:12275）：骰子数取 +0x12，每颗 `rand() % 6 + 1`，按顺序生成；若传入了指定点数（遥控骰子），只用 1 颗且不调用 rand【代码确认】。
- 调用顺序会影响后续所有结果；要复现必须保持相同的调用次序（台词选择里的 `rand()&1`、AI 回合中“用卡还是用道具”的那次 `rand()&1` 都会消耗一次）。

### 7.2 读取原版存档的建议

1. 用 `DataView` 小端读取，按 §5.2 表顺序逐段前进，读完后断言偏移等于文件长度（两份样本都满足）。
2. 魔数不是 0x26 时拒绝（原版读档函数本身不查，但列表会过滤）。
3. 名字、股票名等指针字段丢弃，按角色号、`阶段*4+地图` 重建。
4. 地图块按**字节偏移**解析，整体保存为 `Uint8Array` 再解析出 BoardState；回写时只改动已知字段，未知字节保持原样，就能逐字节往返。
5. 未完全理解的字段（地图对象 +1/+4/+5、0x4990f0 等）放进 `raw`，原样写回。
6. 尾部每玩家快照可以按 §5.5 解析为 `timeMachine`；若暂不支持时光机，也应原样保存以便回写。
7. 字符串是 Big5（台湾繁体）。
8. 读档后按原版行为重新播种（§4.2）；若要可复现，在重制版自己的存档格式里另存 RNG 状态。
9. 判定玩家已破产：control = 0 且 +0x64 = 0。

### 7.3 AI 实现顺序建议

先按 §3.2 的回合流程搭框架，再实现 §3.3 中已确认的数值规则（买地保底、无条件加盖、银行比例调整、借款/还款、股票买卖、拍卖出价、岔路随机），所有随机调用都走 §4 的 LCG 并保持原版调用次序；卡片/道具的评估函数按其他文档补充。原版的几个缺陷（敌意值 double 当 int、商店卖卡格位当卡号）建议先按原样复现，再用开关提供修正版本。
