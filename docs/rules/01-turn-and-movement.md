# 01 回合流程、开局设置与移动（大富翁4 v3.11 规则还原）

> 适用版本：rich4.exe v3.11（SHA256 `5a90aee2…69550`，与 `upstream/rich4` 逆向项目一致）。
> 依据：只用逆向资料（`upstream/rich4/asm`、`csrc`、`docs`）和原版地图数据（`editor/site/assets/map-*.json`）。
> 范围：新游戏设置、回合顺序与阶段、日期推进与周期结算、掷骰、逐步移动、选路与方向、经过与停留、胜负判定。
> 地产、股票、卡片、道具、事件与神明、银行等子系统的细节由其他文档负责，本文只写触发条件和入口函数。

### 0.2 路径与地址缩写

- 路径相对于 `upstream/rich4/asm/`，例如 `player_utils.asm:566` 指 `asm/rich4_player_utils.asm` 第 566 行。`rich4.asm` 是主体文件。

### 0.3 术语

| 术语 | 含义 |
|---|---|
| 行动者（actor） | `rich4_current_player`（0x49910c）的取值。0–3 为玩家；4–7 为 NPC，依次是小偷、强盗、流氓、间谍（名称表 `_rich4_special_player_names`，rich4.asm:49890）；8 为机器娃娃（`tool_jiqiwawa.asm:46` 把当前行动者设成 8） |
| tick | 主循环每帧调用一次状态机 `fcn_0040d7c4`（`main.asm:429`）。实际帧间隔取决于计时器，未核实（见 §11） |
| 剩余步数 | 全局 `0x48baf8`。非 0 表示仍在移动；最后一步落地时为 0 |
| rand() | 原程序 C 库的 `rand`（0x456f2d），本仓库重编译时映射到 msvcrt（`mscrt.ld:16`）。【代码确认】直接读取原版 rich4.exe（只读）在该地址的机器码：`imul edx,[seed],0x41c64e6d; add edx,0x3039; mov [seed],edx; shr edx,16; and 0x7fff`。即 `seed = seed*1103515245 + 12345（mod 2^32）; return (seed>>16) & 0x7fff`，取值范围 0..32767。`srand(x)`（0x456f50）把 seed 直接设为 x。开局、读档和每日结算都会调用 `srand(GetTickCount())` |

【代码确认】`new_game.asm`：`_rich4_draw_game_config_menu`（462）、`_rich4_init_new_game_callback`（1263）、`_rich4_init_new_game`（3749）；数据表在 4909–4970；标签字符串（Big5，已解码）在 4826–4870。C 版还原见 `csrc/game_init.c`。

界面行为：

- 每一行都是下拉列表，单击列表项直接写入下标，不存在循环或夹紧逻辑（`new_game.asm:1908`）。【代码确认】
- 首次进入（参数 a0 = 0）时，用 memset 把 7 个 dword 清零，再设人数下标 = 2、资金下标 = 1，`game_map` = 0（`new_game.asm:3818-3842`）。
- 第二次及以后（例如关卡模式过关后），各下标由上一局的实际数值反查得到（3844–3896）。
- 减少人数时，会丢掉编号 ≥ 新人数的已选角色（1923）。

“土地權限”的含义：

- 买地时，若下标非 0，用 `0x4751f0` 中的打包日期增量 {0, 0x20000, 0x10000, 0x600, 0x300, 0x100}，即 +2 年、+1 年、+6 月、+3 月、+1 月，算出到期日，写入地块 +0x30（土地）或 +0x34（设施）（`core_actions.asm:1056-1068`、1707）。【代码确认】
- 每日结算中，若到期日等于当天，地块变为无主（§4.3）。到期的具体效果由地产文档负责。

**game_stage**（0x4991b6）：主菜单第 5 个按钮（返回值 4）把它设为 1 再进入新游戏；返回值 0 时保持 0（`csrc/main.c` 中 `WinMain` 的 switch）。地图编号 `global_map_id = game_stage*4 + game_map`，共 8 张图（`docs/map.txt`）。【代码确认】

### 2.2 角色选择

【代码确认】`new_game.asm:1669-1710`、2003、2404-2450、4155。

- 12 个角色，编号表见 `docs/characters.txt`。同一角色不能被选两次。
- 已选数量必须小于人数时才能继续选；点击已选角色会取消选择。
- 按“确定”至少需要选 1 个。之后每 10 个界面 tick，系统从未选角色中用 `rand() % 未选数` 随机抽一个补进下一个空位，并给该槽的选择项置位 31，表示这是电脑玩家。
- 因此人类总是占前 k 个槽，电脑占剩余的槽。
- 开局时 `player.+100 = (位31 ? 2 : 1)`，即 1 = 人类、2 = 电脑。玩家首次上场时把这个值复制到 `who_plays`（rich4.asm:11544 一带的 `fcn_00418c55`）。
- 人类人数存入 `_num_human_players`（0x499104）。

### 2.3 初始化流程（按“确定”之后）

【代码确认】`csrc/game_init.c`，对应 `new_game.asm` 4000–4300。

1. 人数 = 下标 + 2；当前行动者 = 0；`game_initial_fund` = 资金表[下标]。
2. 卡片和道具持有清零。卡片商店库存 = `card_table[i].init_amount`。道具商店库存 `0x497320[0..7]` = `tool_table[i].max_amount`，前 8 种道具都是 10。
3. 对每个玩家槽 i < 人数：
   - **起始道具**：依次调用 `_rich4_receive_tool(i, t)`，t ∈ {1, 2, 3, 4, 8, 9}，即机器娃娃、路障、地雷、定时炸弹、遥控骰子、机器工人各 1 个。
     - `_rich4_receive_tool` 的规则：持有数 ≥ 9 时不给；t ≤ 8 时要先从商店库存扣 1，库存为 0 时不给（`game_init.c` 中的 `fcn_00445a4d`）。
   - 从角色模板复制整个结构体（`rich4_characters.c`）。模板中的 who_plays = 0，所以玩家此时尚未上场。
   - **资金分配**（以 `+100` 判断人类或电脑）：
     - 人类：现金 = 存款 = 总资金 / 2（整数除法）。
     - 电脑：现金 = trunc(init_cash_ratio × 总资金 / 100.0)，存款 = 总资金 − 现金。

       | 角色 | init_cash_ratio |
       |---|---|
       | 约翰乔 | 50 |
       | 沙隆巴斯 | 40 |
       | 忍太郎 | 70 |
       | 钱夫人 | 60 |
       | 阿土伯 | 40 |
       | 莎拉公主 | 70 |
       | 宫本宝藏 | 50 |
       | 糖糖 | 40 |
       | 乌咪 | 60 |
       | 孙小美 | 50 |
       | 小丹尼 | 55 |
       | 金贝贝 | 80 |

   - **交通工具**：traffic = 设置的行进方式，`ndices = traffic + 1`。若 traffic ≠ 0，从商店库存 `0x497323[traffic]` 扣 1（机车扣库存[4]，汽车扣库存[5]）。所骑的车不计入玩家的道具持有数。
   - 点券：模板中为 0，初始化不改动，所以为 0。
   - 超出人数的槽整体清零。
4. **NPC 初始状态**：复制默认表 `0x47ecec`，其中 f10 = {1, 1, 2, 2, 3}。f10 的含义：0 在地图上活动，1 在监狱（`prison_utils.asm:185` 写 1），2 在医院（`hospital_utils.asm:185` 写 2），3 不在场（机器娃娃未使用）。所以小偷和强盗开局在监狱，流氓和间谍开局在医院，机器娃娃不在场。
5. 物价指数 `price_index` = 1；已过天数 `0x4990e4` = 0；已过月数 `0x499084` = 0；股市休市计数等清零。股票按 `global_map_id` 复制初始表。
6. **日期不重置**：新游戏沿用 `global_rich4_cfg.date`（0x497160），见 §4.1。

### 2.5 首回合“空降”上场

【代码确认】rich4.asm:1008 `fcn_0040829d`，以及 11494 `fcn_00418c55`。

- 某玩家第一次轮到时，若 xpos = ypos = 0，先调用 `_rich4_find_random_unoccupied_node` 为其选节点（`node_utils.asm:11`）。候选条件：
  - 状态字 `& 0x80ffff00` 为 0，即无人、无物件、位 31 未置；
  - 节点至少有一个邻居（判断 +24..+31 两个 dword 是否非 0）。
  - 在候选中用 `rand() % 候选数` 均匀抽取。
- 再从该节点的非空邻居中用 `rand() % 数量` 随机选一个作为 last_node（这里不检查单向位）。朝向 = 方向(last_node → node)。
- 播放空降动画后，`who_plays` = +100（1 人类 / 2 电脑）。
- 因此每个玩家的出生点各自独立随机，且不会与已上场的人或物件重叠。

## 3. 回合顺序与回合内阶段

### 3.1 轮转算法（结束回合 → 下一个行动者）

【代码确认】rich4.asm:11704 `fcn_00418ebd`。

```
结束当前回合():
  若 当前 == 8（机器娃娃）:
      当前 = 娃娃的主人（special[4].owner）；若娃娃的 f10 == 0 则设为 3（收回）
      不推进轮转，直接返回        # 主人继续自己的回合
  若 当前 < 4 且 who_plays & 0x30（旅馆进出的附加一步）:
      清掉 0x30 标志并结束，不推进轮转
  新的一天 = false
  循环:
      当前 += 1
      若 当前 == 人数: 当前 = 4                 # 跳到 NPC 段
      若 当前 == 8:   当前 = 0; 新的一天 = true   # 一轮结束
      若 4 ≤ 当前 < 8 且 special[当前-4].f10 != 0: 继续循环   # 不在场的 NPC 跳过
      若 当前 < 4 且 who_plays == 0 且 xpos != 0: 继续循环   # 破产者（乞丐）跳过
      否则 跳出
  若 新的一天: 每日结算()                        # fcn_0041cf67，见 §4.2
  回合开始(当前)                                  # fcn_0041c84f，见 §3.3
  若 新的一天 且 设置“自动存档”开启: 自动存档      # _rich4_save_game_to_file(0)
  置 当前行动者的回合开始待处理标志（+0 位7）
```

由此得到的规则：

- 一轮的顺序是：玩家 0 → 1 → …… → 人数−1 → 在场的 NPC 4 → 5 → 6 → 7 → 日期 +1 → 玩家 0。【代码确认】
- 一天就是一轮。日期在“玩家 0 的回合开始之前”推进，所以新游戏的第一天，从玩家 0 开局到全体走完一轮才算过一天。【代码确认】

### 3.2 回合开始：状态计数器（fcn_0041c84f）

【代码确认】`core_actions.asm:4101-4730`。

开头先调用 `fcn_0042915a`（股票模块）和 `fcn_00436a5a`（银行模块），两者只是接口，见对应文档。若该玩家 who_plays = 0，或游戏已结束（0x46caf8 ≠ 0），直接返回。

**计数器约定**：每个计数器是 1 字节。

- 字节为 N（1..127）：本回合仍生效；在回合开始时减 1。减到 0 时把字节改成 0x80，表示“已到期，等待下一回合处理”。
- 字节为 0x80：本回合开始时执行解除动作，并把字节清零。
- 结果：设置 N 天的状态会实际影响 N 个自己的回合，在第 N+1 个回合开始时解除。（例外：消失计数用低 6 位计数，位 6 是附加标志。）

**处理顺序**（玩家 0–3）：

1. 住宿 +50：若为 0x80，调用 `fcn_0040d6be` 离开旅馆（设置 who_plays\|=0x10，朝向下一节点）；否则减 1，减到 0 时置 0x80。

3. 坐牢 +52：若为 0x80，调用 `_rich4_release_player_from_prison`；否则减 1，到 0 置 0x80。
4. 住院 +53：若为 0x80，调用 `_rich4_release_player_from_hospital`；否则同上。
   - 对玩家，两者都只调用 `fcn_0040d6be`（置 0x10，与离开旅馆相同），字节仍是 0x80，要等行动分派时“走出门”那一步才清零；那一步在门口格（ref 8001 / 8002）按最后一步做逐步处理（地雷、路障等都生效），没被送回去才照常行动。详见 [06 §9.3.1](06-events-gods-places.md)。
5. 若 +50..+53 全为 0（人在路上）：
   - 冬眠 +54 为 0x80：清零，恢复动画。
   - 梦游 +55 为 0x80：清零，从 +102/+103 恢复梦游前的交通工具和骰数。前提是还持有对应的车道具（工具槽 4 机车 / 5 汽车），否则改为步行 1 骰。

## 4. 日期、每日结算与周期触发

### 4.1 日期表示与算法

【代码确认】`date_utils.asm`。

- 日期打包成 `year<<16 | month<<8 | day`，保存在 `global_rich4_cfg + 8`（0x497160）。
- 闰年规则只看 `year % 4 == 0`（`_rich4_days_from_1998`，第 11 行）。2100 年会被错误地当成闰年，在 1998–2099 范围内没有影响。
- 月天数表在 `0x47638f`：{31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31}，闰年 2 月取 29。
- 日期工具函数：

| 函数 | 作用 |
|---|---|
| `_rich4_days_from_1998(d)` | 返回自 1998-01-01 起的天数，从 0 开始。只能处理 1998 年及以后 |
| `fcn_00452117(&d)` | 日期 +1 天。月份进位时返回 1（新月份），否则返回 0 |
| `_rich4_parse_date(d, &wd, &mdays)` | 星期 = `(days + 4) % 7`（0 = 星期日；1998-01-01 是星期四），并给出当月天数 |
| `fcn_004521cb(d, delta)` | 按打包字段直接相加；月份超过 12 时减 12 并进 1 年。**不修正日**，例如 8/31 加 1 个月得到不存在的 9/31 |
| `fcn_0045218f(d, n)` | 日期 + n 天 |
| `fcn_004521aa(a, b)` | 返回 b − a 的天数 |

**起始日期**：

- 启动时读取 RICH4.CFG 后，**总是**用系统当天日期覆盖配置中的日期（`rich4_config_file.c:32-48`，这是 C 还原，对应原地址 0x411e8f）。【代码确认】
- **原版会夹紧日期**：系统年份 < 1998 时改为 1998-01-01，> 2010 时改为 2010-01-01。【代码确认】依据是直接读取原版 rich4.exe（只读）0x411e8f 处的机器码：`cmp dx,0x7ce; jae …; mov word [esp+2],0x7ce; 日=月=1` 和 `cmp dx,0x7da; jbe …; mov word [esp+2],0x7da; 日=月=1`。本仓库的 C 还原把这段放在默认关闭的宏 `USE_RICH4_DATE_DEFAULT` 下，所以重编译版本不会夹紧，重制时应以原版为准。

- 新游戏不重置日期，从当前配置日期开始；游戏进行中这个字段就是“当前游戏日期”，存档也会保存它（`save_files.asm:134`）。

**农历表上限**：农历表 `0x47639c` 每天一个 dword，共 8399 项，覆盖 1998-01-01 到 2020-12-31（rich4.asm:41387-49786）。之后的日期查节日时会越界读取，见 §4.4。【代码确认】

### 4.4 节日系统

【代码确认】rich4.asm 中的 `fcn_004521f0`（查找）和 `fcn_00452444`（每日处理）。

**表结构**：`0x47ff4a` 起，按 `global_map_id` 分 8 张表，每张 24 条，每条 12 字节。

| 偏移 | 含义 |
|---|---|
| +0 | flag。0x80 = 跳过此条；其它非 0 值表示休息日 |
| +1 | 类型：0 公历固定日期；1 农历日期；2 某月第 N 个星期 W |
| +2 | 月 |
| +3 | 日，或 N |
| +4 | 星期 W |
| +5 | 效果位：1 播放画面，资源号在 +6、参数在 +8；4 播放节日音乐，资源号在 +10；8 每个在世玩家获得一张随机卡；2 用途未知 |

**匹配规则**：

- 类型 0：今天的月/日等于条目的月/日。
- 类型 1：用今天查农历表，取低 16 位与条目比较。
- 类型 2：先求当月 1 日的星期 w1。第一个 W 的日期为 `W − w1 + 1`；若 W < w1 则改用 `W + 7 − w1 + 1`。再加 `(N−1) × 7`。若结果超过当月天数则不匹配。
- 按表中顺序取第一个匹配且 flag 不含 0x80 的条目。

**实现上的副作用**：查找循环中，类型 1 的分支会把“今天的比较值”改写成农历月日，之后检查的条目都拿农历值去比较。也就是说，一张表里排在第一个农历条目之后的公历条目，实际上是用农历日期匹配的。原版表中（见下）农历条目都排在末尾，影响很小。【代码确认：`fcn_004521f0` 中 `edi` 在农历分支被覆盖】

**效果**：

- 效果位 8：对每个在世玩家调用 `_rich4_player_receive_random_card`，并提示“得到%s”。
- 播放画面期间临时关闭“合并视图”设置（`cfg+5 == 1` 时暂时改为 0）。

**原版表内容摘要**（解码自 `0x47ff4a`；`flag=0` 表示当天不休市）：

- 台湾（地图 0）：
  - 公历：1/1（画面）、2/14、3/29、4/1、4/4、4/5、5/1、8/8、9/28、10/10（画面）、10/25、10/31、11/12、12/25（画面 + 音乐 + 送卡）；
  - 5 月第 2 个星期日；

## 5. 掷骰

### 5.1 点数计算 fcn_00419572

【代码确认】rich4.asm:12275。

```
掷骰(强制值):
  若 强制值 != 0:  骰数 = 1; 骰[0] = 强制值             # 遥控骰子
  否则: 对 i in 0..ndices-1: 骰[i] = rand() % 6 + 1    # 每颗 1..6 均匀（按 rand 模 6 近似）
  播放骰子动画（动画速度表 0x475264 = {5, 3, 2}，按设置的游戏速度 0/1/2 取值）
  返回 Σ骰[i]
```

- 强制值来自 `fcn_00447285`：读取并清零字节 `0x475dd8`。遥控骰子道具在出发前把选定的点数 1..6 写入这里（界面有 6 个按钮，`ui_use_tool.asm:992` `fcn_00446774`），然后立即调用 `fcn_0040dd1f`（`tool_yaokongtouzi.asm`）。
- 每颗骰子 `rand() % 6`：32768 = 6×5461 + 2，所以点数 1、2 的概率是 5462/32768，3–6 是 5461/32768，偏差可以忽略，但逐帧复现时要用同样的取模。
- 步数等于点数和，没有额外修正。“乌龟”和“停留”在掷骰之前就被处理掉了（§3.6）。

### 5.2 骰子数由谁决定

- `ndices` 是持久字段，上一回合的选择会保留。【代码确认】
- 改变交通工具时强制设定骰数：

| 动作 | 结果 | 出处 |
|---|---|---|
| 开局 | ndices = traffic + 1 | §2.3 |
| 使用机车道具 | traffic = 1，ndices = 2；若原来骑汽车，汽车退回道具栏 | `tool_jiche.asm:26-56` |
| 使用汽车道具 | traffic = 2，ndices = 3；若原来骑机车，机车退回道具栏；已经是汽车时道具无效 | `tool_qiche.asm` |
| 下车（`fcn_00447c00`） | 车退回道具栏，traffic = 0，ndices = 1 | — |
| 车被毁（`fcn_0040cd07`，被地雷、炸弹、恶犬等波及） | 车退回**商店库存**（不是个人道具栏），traffic = 0，ndices = 1，who_plays\|=0x40 | — |

- 人类可以选择骰子数：
  - 鼠标面板：机车可选 1..2，汽车可选 1..3（rich4.asm:10670-10735）。
  - 快捷键（配置偏移 0x26，默认 D）：机车在 1↔2 间循环，汽车 1→2→3→1；步行时无效。停留计数 +56 ≠ 0 时快捷键无效（`keyboard_hook.asm:262-280`）。
  - 结论：人类骰数范围 = 1 .. traffic+1。【代码确认】
- 骰数与车绑定，**不会**因为“步行”而大于 1。

### 5.3 AI 选择骰子数 fcn_004221c0

【代码确认】rich4.asm:12433-12590。

**机车或汽车且身上有定时炸弹时**（看炸弹剩余寿命）：

- 汽车：寿命 < 15 时 1 骰；寿命 ≥ 15 时 3 骰。
- 机车：寿命 < 15 时 1 骰；否则保持 2 骰。

**否则**，用 `fcn_0040b221(p, 5)` 预测前方 5 个节点（§6.6），统计：

- good = 前方节点关联的土地或设施中，无主或属于自己的个数；
- bad = 属于他人的个数；没有关联地块的节点不计。

| 交通工具 | 条件 | 骰数 |
|---|---|---|
| 汽车 | 先设为 3 | 3 |
| 汽车 | good = 0 且 bad > 2 | `2 + (rand() & 1)`，即 2 或 3 |
| 汽车 | good ≥ 2 且 bad ≤ 1 | 1 |
| 机车 | 先设为 2 | 2 |
| 机车 | good = 0 且 bad > 2 | 2 |
| 机车 | good ≥ 2 且 bad ≤ 1 | 1 |

- 步行不调整，保持 1。
- 预测路线的分岔是随机抽取的，会消耗 rand；它与实际走的路线**无关**，实际路线在移动时重新随机。

## 6. 移动

### 6.1 一步的移动 fcn_0040c05c

【代码确认】rich4.asm:5903。

每走一段时：

1. 选下一节点（§6.2）。
2. `last_node = node`，`node = 下一节点`，在新节点上更新附属物件的位置。
3. 清旧节点的占位位，置新节点的占位位。**节点号和占位在动画开始的那一刻就更新了。**
4. 动画帧数 = round_toward_zero(距离 / 速度)，至少 1。速度单位为像素/帧，取表 `0x4749d8`：

   | 交通工具 | 速度 |
   |---|---|
   | 步行 | 8 |
   | 机车 | 12 |
   | 汽车 | 16 |
   | 工程车 | 8 |

   旅馆进出（0x30）或特殊动画套时，帧数 = 距离 × 0.125。NPC 也一样，即 8 像素/帧。
5. 朝向 = 方向(last_node → node)（§6.3），每段开始时更新。
6. 帧数用完后，坐标对齐到节点，函数返回 1，状态机随之记一步（§3.7）。

### 6.2 选路规则：分岔对所有人都是随机的

【代码确认】rich4.asm:5975-6013（玩家）、6058-6080（NPC）。

```
候选 = []
对 j in 0..3:
    n = 邻接[j]
    若 n == 0: 跳过
    若 n == last_node: 跳过                         # 不走回头路
    若 状态字 & (0x40000000 >> j): 跳过              # 单向或封闭
    候选.append(n)
若 候选为空: 下一节点 = last_node                    # 死路掉头，不消耗 rand
否则: 下一节点 = 候选[rand() % len(候选)]           # 只有 1 个候选时也调用一次 rand
```

- **人类玩家在岔路口没有选择权**，与电脑使用同一段随机代码。代码中不存在任何让玩家选路的分支。
- 重制版：岔路改为每个玩家预先决定的直走/左转/右转，画在地图上（rand() 次数不变），见 [14 岔路箭头与路口](14-forks-and-junctions.md)。
- 每个候选的概率为 1/候选数（不考虑 rand 模偏差）。
- 只有 1 个候选时也会调用一次 rand()，重制时若要逐帧复现随机序列，需要保留这次调用。
- 死路时直接回到 last_node（不检查单向位）。

### 6.3 方向计算 _rich4_calculate_direction

【代码确认】`calculate_direction.asm`。

- 输入为像素差 (dx, dy) = (目标 − 起点)。函数取 y' = −dy（屏幕 y 轴向下，取反后向上为正），计算 16 位定点角度：`angle = atan2(y', dx)`，0x10000 为一整圈，0 指向 +x，逆时针增加。
  - 实现方式：先用 |min|/|max| 查 2049 项反正切表（0x48242c），再按象限修正。
- 扇区 `s = ((angle >> 12) + 1) >> 1 & 7`，即四舍五入到最近的 45°。
- 方向 = 表 [2, 3, 4, 5, 6, 7, 0, 1][s]，等价于 `dir = (s + 2) & 7`。

| dir | 屏幕方向 | dir | 屏幕方向 |
|---|---|---|---|
| 0 | 下（+y） | 4 | 上（−y） |
| 1 | 右下 | 5 | 左上 |
| 2 | 右（+x） | 6 | 左（−x） |
| 3 | 右上 | 7 | 左下 |

- (0, 0) 时角度为 0，所以 dir = 2。
- 恰好在 22.5° 边界上的取舍由定点查表决定。重制时若要逐像素一致，应移植查表算法，而不是用浮点 atan2。

节点间方向 `fcn_00407a8c(a, b)` = calculate_direction(b.x − a.x, b.y − a.y)（rich4.asm:971）。方向只用于选精灵和“转向”运算，不影响选路。

### 6.4 回头或转向 _rich4_change_player_direction

【代码确认】rich4.asm:6417。由卡片或魔法屋等调用，调用方见其它文档。

```
dir = (dir + 4) & 7
候选 = 邻接中 非0、未被单向位封闭、且 != last_node 的节点     # 也就是原来“前方”的节点
若 候选非空: last_node = 候选[rand() % len]
否则:       last_node = 0
```

效果：

- 在普通双向路段上，原来前方的那个邻居变成了“来路”，下一步只能走回原来的 last_node，所以实际方向反过来了。
- 在三岔路口，last_node 被设为随机一条前方支路，下一步可能走另一条前方支路，也可能走原来的来路。
- 若前方没有候选，last_node = 0，下一步可以走任何邻居。

## 8. 胜负判定

### 8.1 每日检查 fcn_0041d89e

【代码确认】`core_actions.asm:5615-5790`。它在每日结算中、日期 +1 且已过天数 +1 之后调用（§4.2 第 4 步）。

```
若 天数上限 == 0 且 目标资产 == 0: 不检查
最富者 = 在世玩家中 _rich4_calculate_player_wealth 最大者     # 严格大于才替换，所以平局时编号小者优先
若 最富者资产 == 0: 跳过天数判定（只看目标资产，此时目标资产必然不满足）
若 (天数上限 != 0 且 已过天数 >= 天数上限) 或 (目标资产 != 0 且 最富者资产 >= 目标资产):
    最富者获胜：说胜利台词；其余所有玩家 who_plays = 0
    若 人类人数 == 1:
        若 获胜者是人类: 其余角色在关卡表 0x4990f4 中标为 2（已击败）；结束码 = 2（过关）
        否则（电脑获胜）: 进入失败流程 fcn_00407842(1)，结束码取其返回值
    否则: 获胜者为人类时结束码 = 3，否则 = 1
```

- “资产”的计算口径（现金、存款、贷款、股票、地产）由地产文档负责（`_rich4_calculate_player_wealth`）。
- 天数上限的含义：730 天以“每日结算次数”计数，从新游戏开始累计。开局时为 0，第一次结算后为 1。

### 8.2 破产引起的结束

【代码确认】`player_bankrupt.asm:50-310`。破产的资产处理由地产文档负责，这里只写结束判定。

- 破产者 who_plays = 0，但保留在原节点并恢复占位位，成为“乞丐”（§7.1 第 2 步）。+28（现金）之后的状态字段全部清零；所有人对他的敌意清零；角色在关卡表中标为 2。
- 若人类人数 == 1 且破产者是人类：失败流程 `fcn_00407842(0)`。
- 否则统计在世玩家数 A 和在世人类数 H：
  - H == 0：结束码 = 1（电脑获胜，游戏结束）。
  - A == 1（唯一幸存者是人类）：说胜利台词；人类人数 == 1 时结束码 = 2，否则 = 3。
  - 否则游戏继续。
- 投降（選項中的“投降”，`ui_options.asm:2745` `_rich4_player_surrender`）直接调用破产。人类人数 > 1 时可能触发死神（`_rich4_call_god_of_death_entry`）。

### 10.2 引擎结构建议

1. **随机数**：集中到一个 `Rng` 接口，实现原版 `rand()`，即 §0.3 的 LCG，取值 0..32767。
   - 记录每次调用的位置，便于和原版对拍。下面这些调用都会改变后续序列，必须保留：只有 1 个候选时的选路 rand、AI 路线预测、`rand() & 1` 决定 AI 用卡还是用道具。
   - 原版每天 `srand(GetTickCount())`，无法完全复现。建议重制版提供一个“确定性模式”：用种子代替 tick。
2. **回合主循环**写成显式状态机：`turnStart → (humanWait | aiActions) → depart → rolling → moving(step*) → landCountdown(5) → landEvent → endCountdown(n) → nextActor`。原版的 tick 计数（5、2、8、3）应作为可配置的表现延迟，与规则逻辑分离。
3. **逐步处理**作为纯函数 `onStep(actor, node, stepsLeft)`，按 §7.1 的顺序执行。由它返回“是否强制停下”（路障、地雷、炸弹爆炸、恶犬）。
4. **节点的占位和物件**不要再塞进状态字，用独立结构保存。但“选点要求无人、无物件、位 31 未置”这一规则要保留。
5. 选路函数与方向函数分开实现。方向用定点查表复刻，或保证在 22.5° 边界附近结果一致。
6. 计数器用 `{value, expired}` 表示，统一实现：减到 0 时标记 expired，下回合开始时执行解除动作。不要直接复制 0x80 位。
7. 日期运算按 `year % 4` 规则实现。“加月”运算要复刻“不修正日”的行为，因为它影响土地到期是否会发生（§11 Q6）。
8. 节日查找要复刻“农历条目覆盖比较值”的副作用（§4.4），或者在数据层面保证农历条目排在最后（原版表已满足）。
9. 胜负检查挂在“日期 +1”之后。破产检查挂在破产事件之后。

### 10.3 回合伪代码（总览）

```
loop:
  actor = state.current
  if actor 是首次上场的玩家: spawnRandom(actor)
  r = canAct(actor)                         # fcn_0040c912(0)
  if r == 0: wait(3); endTurn(); continue
  if r == 'dream': depart(actor)            # 自动出发
  elif human: await UI(...); await go()     # 只有 go() 才出发
  else: aiPreRoll(actor); if 还在路上: aiChooseDice(actor); depart(actor)
  # depart：停留 → 原地再触发；乌龟 → 1 步；否则掷骰
  for each step: moveOneSegment(); onStep(actor, node, stepsLeft)
  wait(5)
  if 仍在路上 && 不是 NPC: ret = landEvent(actor, node) else ret = 0x83
  wait(ret & 0x7f); endTurn()
endTurn():
  advance actor (§3.1); if wrapped: dailyUpdate(); if gameOver: stop
  turnStartCounters(actor)
```
