# 14 岔路箭头与路口（重制版新增）

> 这是**重制版自己的新规则**，不是原版内容。原版的岔路规则见 01 文档 §6.2、§6.4、§6.6。
> 代码：`game/src/core/modules/forks.ts`（规则、`walk()` 预测、`plan()`）、`game/src/ui/fork-arrows.ts`（地图上的箭头），测试 `game/src/core/modules/forks.test.ts`、`game/src/ui/fork-arrows.test.ts`。

## 1. 原版怎么决定岔路方向

全部来自反汇编，【代码确认】。

- **每走一步都随机选**：`fcn_0040c05c`（rich4.asm:5903）。玩家分支在 rich4.asm:5968–6013（0x40c12c–0x40c1a9）：
  对邻接槽 j = 0..3，跳过空槽、跳过 `last_node`（玩家结构 +14）、跳过状态字 `& (0x40000000 >> j)`（单向／封闭），
  剩下的放进候选表；候选为空就回到 `last_node`（不调用 rand）；否则 `rand() % 候选数`（`call _libc_rand`，rich4.asm:6002）。
  **只有一个候选也调用一次 rand()**。
- **全局，不分玩家**：用的是 C 运行库唯一的 `rand()` 状态，所有玩家、NPC、AI 预测共用一个序列；岔路口本身不记任何状态，
  每次有人到达都重新抽。
- **人类和电脑一样**：同一段代码，没有任何让人类选路的分支或界面（01 §6.2、待实测 Q5）。
- **NPC 和机器娃娃**（行动者 4–8）：同样的规则，作用在特殊角色结构上（rich4.asm:6223–6265，rand 在 :6253）。
- **转向卡、魔法屋「向後轉」**：`_rich4_change_player_direction`（rich4.asm:6417）只改朝向和 `last_node`：
  `dir = (dir + 4) & 7`，`last_node = 前方候选[rand() % 个数]`（没有前方候选时为 0）。在三岔路口，转身后的下一步可能走另一条前方支路，
  也可能走原来的来路（01 §6.4）。
- **路线预测**：`fcn_0040b221`（rich4.asm:4666，rand 在 :4750）和反向的 `fcn_0040b343`（:4779）按同一规则向前模拟 n 步，
  岔路同样随机抽，**和之后真正走的路无关**。电脑选骰子数（01 §5.3）、电脑用道具和卡片选目标都用它。
- 原版每天按系统时间重设随机种子（07），所以玩家既看不到、也无法预测岔路会往哪走。

## 2. 重制版规则：每个角色自己的岔路箭头

**岔路**：有 3 或 4 条相邻路格、并且至少从其中一条路进来时还剩 2 条以上可走（不回头、不走被单向位封闭的槽）的路格。
4 条路相交就是十字路口。原版的地图记录本来就有 4 个邻接槽（01 §1），引擎不需要另外的格式。

2026-10-23 起的规则是「**走最久没走的路**」（下面 1–9 条，测试开关 `FORK_LRU`）；之前的「0–5 的选择」写在本节后面「2026-10-18～10-22 的规则」，保留作对照。

1. **每个玩家在每个岔路口有自己的记录**：这个路口的每一条路（用**绝对的**相邻路格编号记，不是左转右转）他最后一次是什么时候走的——
   走进来、走出去都算“走过”。时间用每个玩家自己的计数（`tick`，每走出一次路口通常加 2：先记来路，再记去路）。四个玩家互不影响。
2. **走出岔路口时**：在可走的路（不含来路、不含封闭的槽）里，先挑**这个玩家在这里从来没走过的路**；都走过了，就挑**最久没走的那条**。
   一样久（都没走过）时，按这个玩家在这个路口的**开局顺序**（第 6 条，每局随机）决定。
   - 所以经过一次路口，他在这里的箭头**立刻**指向一条没走过的路；每条路轮流走到，走完一轮再照“最久没走”循环。
   - 从同一边一再经过：T 字路口从“竖”进来两条路交替；十字路口从同一边进来，三条路轮流。
   - 来路也算走过：从南边进来、往北走出去之后，下次从东边进来，南、北都走过了，就往西（没走过的那条）。
   - 只剩一条路时都走那条；死路照原版掉头。没有来路（转向卡转身后前方没有路，`last_node = 0`）时，可走的路全部是候选（十字路口 4 条）。
   - 和从哪个方向来无关地定义清楚：记录的是绝对的路，到达时才按“这次能走的路”挑，所以从任何一边来都只有一个答案。
3. **随机数**：走出路口那一步**照样抽一次 rand()**（原版这一步本来就抽一次），只是结果不用。所以每一步消耗的 rand() 次数和原版、和旧规则完全相同，
   骰子、事件等后面的随机数序列不会因为换规则而整个错位；路怎么走只由记录决定，完全可预测。
   不论是路过还是从这个路口出发（停在路口上，下一回合出发时也照箭头走）都算“走出”。
4. **谁照箭头走**：
   - 玩家（人类、电脑、托管、梦游中的玩家）：照自己的记录走，并且记下这次的来路和去路。
   - 机器娃娃：照**主人**的箭头走（替主人清的正是主人要走的路），**不**改记录。
   - NPC（小偷、强盗、流氓、间谍）：不看箭头，照原版随机走。
   - 歌舞伎町拿着黑帮的电脑会避开监狱（21 §4.1）：照它**实际**走的那条路记录。
5. **预测**：电脑选骰子数、选道具卡片目标、聪明电脑（`smart-ai.ts` 的 `route`）、机器娃娃、歌舞伎町的黑帮避监狱和确变选骰子、大富豪模式电脑用遥控骰子去车站机场，
   都按**那个玩家自己**的箭头往前走（`Forks.walk`），而且**把这段预测里自己经过的路口也算进去**：同一段路线第二次经过同一个路口，走的是那时会走的路。
   所以预测的路线就是他真的会走的路；记录不变；原版预测每一步抽的 rand() 照抽。
6. **开局＝每局不同的箭头**：独立的随机数流 `Rng(daySeed(种子 ^ 0x0f0e5a, 0))`，玩家按编号、岔路按路格编号，把每个路口的可走的路洗牌（Fisher–Yates，`rand() % (i+1)`），
   得到每个玩家每个路口的开局顺序（`order`）。所以开局时每条路被选中的机会一样（T 字路口各 1/2，十字路口各 1/3），每局、每张地图都不一样；同一个种子一定相同。
   不消耗规则用的 rand()。没有设定开关：永远每局随机。
7. **转向卡、向後轉**：原版规则不变（随机挑一条前方支路当来路）；之后走出路口时，以新的来路判断哪些路可走、记录来路。
8. **瞬间移动**（传送机、送医院、坐牢、空降、乞丐被挪走等）不算“走出路口”，记录不变。
9. **存档**：`modules.forks` 存 `order`（开局顺序）、`used`（每个玩家：路口 → 路 → 最后一次走的时间）、`tick`，版本 `v = 3`，读档后箭头不变。
   其他版本的存档（全体共用 `arrows`、没有 `v` 的 直走/左轉/右轉、`v = 2` 的 0–5 选择）读档时丢掉旧表，改用这一局种子的开局顺序，**记录从空的开始**（大家都当作还没走过任何路）。
   派对模式各台手机从同一个种子算、存档也一样，不用 `Math.random`、不看时钟，所以每台手机走的路都相同（`forks.test.ts`）。

### 画面上看到的箭头 = 实际会走的路

只显示**轮到的玩家**（也就是正在移动的玩家）自己的箭头，用他的角色颜色。箭头画的是**绝对方向**：
从他现在的位置和来路出发，按他自己的箭头一路往前走（`Forks.plan`，用上面第 5 条的预测：经过的路口也算进去），最多 600 步，
每个岔路口画的是他**下一次到那里**时会走的路。2026-10-23 起第二次经过同一个路口也能事先知道，所以不再在那里停下，画面上能看到的箭头更多
（旧规则走到第二次碰到同一个路口就停，因为那里的选择已经重新抽过）。
所以画出来的每一支箭头，都正是他走到那里时会走的路；不在这段路上的岔路口不画箭头；他一走出某个路口，那里的箭头马上换成下一次会走的路（`fork-arrows.ts` 的缓存跟着 `tick` 变）。
**只在真的有得选的地方画**（2026-10-18）：他到那个路口时如果只有一条路可走（例如原版地图的监狱、医院路口从主路经过，牢房那一支被单向位封闭），
那里不画箭头——那支箭头永远指同一边，没有意义。从牢房那一支出来时有两条路，照常画。只是画面（`fork-arrows.ts` `arrowsOf()`，`Forks.plan(p, 600, ways)` 记下每个路口第一次到达时的出口数），规则不变。

### 遥控骰子怎么用

数步数时，到岔路口就看自己颜色的箭头：那就是你会走的路。你的记录只会在你自己走出那个路口时才改变，别人经过不影响你。
（转向卡、传送等会改变来路或位置，箭头会跟着重算。）

### 改动（2026-10-23）：走最久没走的路

用户：「通过一次路口，箭头朝向立刻改变为没走过的路径。不然走了好几个月还一直在一个区域来回绕圈子，根本没机会全图跑。」

### 2026-10-18～10-22 的规则：0–5 的选择（`FORK_LRU` 关）

保留在代码里只给测试对照用（`FORK_LRU.on = false`，存档 `v = 2`），不是设定：

- 每个玩家在每个岔路口有一个 0–5 的数（存 `modules.forks.choices`：路格编号 → 0–5）。
- 走出岔路口时把可走的路（不含来路、不含封闭的槽）按「从来的方向转过去的角度」（地图平面上，从地图上方看；屏幕上每个视角也一样）**从左到右排好**，走第 `选择 % 条数` 条：
  - 3 岔路口（出口 2 条）：选择是双数走左边那条、单数走右边那条——T 字路口从“竖”进来是左转／右转，从“横”进来是直走／转弯，**两条路机会一样**。
  - 十字路口（出口 3 条）：0、3 左转，1、4 直走，2、5 右转，**三条路机会一样**。
  - 只剩一条路时都走那条；死路照原版掉头。没有来路可比时，用玩家的朝向当前进方向（这时十字路口 4 条都可以走，`选择 % 4`）。
  - 这和原版的 `rand() % 候选数`（每条可走的路机会一样）一致，只是事先决定、画在地图上。
- 走出路口的那一刻，只重新决定这个玩家在这个路口的选择：`选择 = rand() % 6`（这个 rand() 就是原版这一步本来要抽的那一次）。
- 开局：同一个随机数流，玩家按编号、岔路按路格编号依次 `rand() % 6`。
- 预测按当时的选择走、选择不变（同一段预测第二次经过同一个路口时仍用旧选择，和实际可能不同）；画面上的箭头走到第二次碰到同一个路口为止。

### 改动（2026-10-18）：每条路机会一样

用户在 iPhone 上玩，觉得每个路口的箭头「每局都指同一边」。实际上开局箭头本来就按种子每局不同，但旧规则的选择是相对的 直走／左轉／右轉（`rand() % 3`）：
T 字路口只有两条出口，三个选择里有两个指向同一条路（从“竖”进来时直走＝右转；从“横”进来时左转或右转之一＝直走），
所以每个 T 字路口有一条路的机会是 2/3（60 个种子统计：歌舞伎町路口 14 从 13 进来，39 次走 15、21 次走 119），看起来就像固定。
原版地图只有监狱（部分有医院）路口，从主路经过只有一条路可走，那里的箭头本来就永远一样（只有从牢房那一支出来时有两条路）。

改成：选择 0–5、按出口从左到右取 `选择 % 条数`（上面 1–3、6），开局和每次走出路口重抽都是这样。每一步仍然只抽一次 rand()，
规则的随机数次数不变，只是走的路不同，所以所有地图的整局记录都变了：`regional-golden.test.ts` 的指纹为此更新一次（`GOLDEN`），
同时保留测试用的 `Forks.legacy`（旧规则，不是设定），用旧规则跑出来的 13 张地图 200 天指纹和改动前**逐位相同**（`LEGACY`），证明除了岔路选择什么都没变。
测试：`forks.test.ts`（每种路口每个方向的对应、不同种子不同箭头、600 局里每条出口约各占一半／三分之一、存读档保留、旧存档重来）。

## 3. 3 岔与 4 岔路口（十字路口）

- 引擎按原版记录支持每格最多 4 个邻居；十字路口从任何一边进来，直走、左转、右转各是一条路。原版地图里，武侠主题（map 5）的银行就在十字路口上，
  城市主题（map 7）有 3 个十字路口。
- 原版其他地图的岔路只有监狱路口（部分地图还有医院路口），通往牢房、病房那一支被单向位封闭：从主路经过时只有一条路可走，选择只在从那条支路出来时起作用。
- 东京：东京（银行）、秋叶原、上野、新宿、品川（田町）、新桥、监狱共 7 个岔路口；大阪（map 101）也是同样的规则。

## 4. 地图设计规则：银行放在路口中间

经过银行就会触发提款机（01 §7.1：事件 14，剩余步数 > 0 时 `atm`；停下时是银行柜台）。
所以银行要放在**路口**（3–4 条路相交的格子）上：不论从哪个方向来、往哪个方向走，经过这个路口就会踩到银行。

- 银行格同时是**银行企业的路格**（企业类别 7，原版每张图的银行格都是银行企业的格子）：董事长室（02 §8.7）要求银行格属于自己控制的企业。
- 银行图标大（124×92），路口的每一条连线都要按大图示的步距（东京 62–84 px，目标 72）。
- 检查：
  - `editor/tokyo_audit.py`：`bank-junction`（`audit()` 和 `--steps` 都会报），原版地图除武侠外都不满足，只作对照。

## 5. 画面

- 箭头是**小**卡通箭头（大小和点券图标差不多），颜色是轮到的玩家的角色颜色（上浅下深的渐变、深色描边、浅色光晕、底边加厚），
  浮在地面上一点、有影子、轻轻浮动，指向他走出这个路口时会走的那条路的方向。
- 位置每个路口算一次（`forkSpot()`，地图坐标）：离路口 56–150 px 的圆环上最近的一个空位，避开道路、事件图标、
  土地和大型用地、景观，也避开在任何一个视角里会被房子、建筑、景观、植物挡住的位置；只有植物挡着时，把那里的植物拿掉（植物只是装饰）。
  位置在地图坐标里固定，8 个视角都一样。
- 箭头平放在地面平面上，所以每个视角都指着地图上的方向；画在事件图标之后、建筑和人物之前。
- 换人或选择改变时，箭头 0.3 秒左右转到新方向（走最短的方向）。
- 小地图暂不画箭头。
- **歌舞伎町**（地图 106，深色霓虹地面、路人很多，2026-10-18）：箭头放大 1.6 倍、加亮色光晕，并且画在路人、建筑、人物**之上**（`drawForkArrows` 的 `opts`），所以 12 个岔路口在三种画风里都看得清楚。
