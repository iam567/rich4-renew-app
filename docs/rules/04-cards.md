# 04 卡片规则还原（大富翁4 v3.11）

> 目标：为 Web/TypeScript 重制引擎提供可直接实现的卡片规则。数值、公式、随机数、判定顺序以原版 `rich4.exe` v3.11 的反汇编为第一依据。
>
> 资料根目录：`rich4-renew/upstream/rich4/`（下文简写：`asm/…` 指 `upstream/rich4/asm/…`，`csrc/…` 指 `upstream/rich4/csrc/…`）。行号以当前仓库快照为准；同时给出原版函数地址/标签，便于行号漂移后定位。
>
> 注意：`csrc/cards.c`、`csrc/cards_ui.c` 是 2018 年的半成品伪 C，有若干错误（例如把卡片面板写成“成功后继续循环”、梦游卡的寄存器混乱）。凡与 `asm/rich4_card_*.asm` 冲突之处，一律以 asm 为准。

### 0.2 记号

- `pi`：物价指数 `_rich4_price_index`（0x4990e8，整数倍率）。卡片中所有“×物价指数”的金额都乘它。
- 玩家编号：0–3 为四个正式玩家槽；4–7 为地图上的“特殊角色”（NPC，`_rich4_all_special_players_state`，0x498e28 起每个 16 字节）。卡片目标为“玩家”时，选择器返回的是位掩码，`count_trailing_zero_u8` 解出编号；编号 ≥4 走 NPC 分支。
- 地块引用号（节点 `+0x20` 字段）：`2001–3999` 为小地块（住宅地，`hlands[id-2000]`，52 字节），`4001–5999` 为大型地块（设施地，`blands[id-4000]`，56 字节）。字段：`+0x17/+0x1c` 价格状态（涨价/查封），`+0x18` 建筑类型，`+0x19` 地主（0=无，否则玩家号+1），`+0x1a` 等级，`+0x1c/+0x22` 地价，`+0x1e/+0x24` 每级建筑价，`+0x30/+0x34` 土地到期日。【代码确认】`csrc/land.h`、`asm/rich4_card_goudika.asm:41-65`
- “同一路段”：小地块记录 `+4` 处的地名字符串用 `strcmp` 完全相同即视为同段。【代码确认】`asm/rich4_card_tianshika.asm`（loc_00443570）
- 玩家状态字节（`player_info`，`asm/rich4_player_info.h`）：`+0x32` 住饭店天数、`+0x33` 消失、`+0x34` 坐牢、`+0x35` 住院、`+0x36` 冬眠、`+0x37` 梦游、`+0x38` 停留、`+0x39` 乌龟、`+0x3d` 同盟剩余天数、`+0x3f` 附身神明（对象号+1）、`+0x40` 身上的定时炸弹（对象号+1）、`+0x41` 同盟对象（玩家号+1）、`+0x42` 冬眠/梦游累计天数、`+0x4c` 起 `hostility[6]`（敌意值）、`+0x66/+0x67` 梦游前保存的交通方式/骰子数。

### 0.3 三个被卡片大量调用的公共函数

1. **转账** `fcn_0041d2c6(payer, payee, amount, flags)`【代码确认】`asm/rich4_player_core_actions.asm:5058-5170`
   - 付款方：flags 无 bit2 时先扣现金、不足再扣存款；有 bit2 时先扣存款再扣现金；两者都不够 → 剩余部分记为 0 并调用 `_rich4_player_bankrupt`。
   - 收款方：flags 有 bit0 → 进现金；无 bit0 → **进存款**。`payee = -1` → 进系统账户（0x499080）。
   - 卡片里用到的都是 `flags=0`：**付款方先扣现金，收款方的钱进银行存款**。
2. **敌意** `_rich4_update_hostility(victim, actor, n)`【代码确认】`asm/rich4_player_utils.asm:1169-1215`
   - `victim == actor` 时无效。`hostility[victim][actor] += n`，结果小于 0 时截为 0；`n<0` 且原值为 0 时不变。
   - **`n>0` 且 victim 的同盟对象正是 actor → 立即调用 `_rich4_end_ally(victim)` 解除同盟。** 所以对盟友使用任何产生正敌意的卡都会解盟。
   - 敌意值供 AI 选目标、嫁祸卡 AI 选人使用（见第 5、6 节）。
3. **ABI 怪癖**（必须注意）：购地卡、拍卖卡、黑卡把一个 **双精度浮点数**压栈传给 `_rich4_update_hostility`，而该函数按 32 位整数读取第 3 个参数，实际读到的是该 double 的**低 32 位**。【代码确认】`asm/rich4_card_goudika.asm:69-85`、`asm/rich4_card_paimaika.asm`（loc_004432ce 之前）、`asm/rich4_card_heika.asm`（loc_00445184 循环）。
   - 例：值为整数且绝对值较小时（如 1000.0 = 0x408F4000_00000000），低 32 位为 0，敌意不增加；带小数时低 32 位是尾数碎片，可能是很大的正数或负数。
   - 重制建议：提供开关 `faithfulHostilityQuirk`。默认按原版复现（`lowDword(float64)`），可选“修正模式”使用设计意图值 `trunc(x)`。

## 2. 通用流程

### 2.1 手牌数据结构【代码确认】

- 每名正式玩家 15 个卡槽：`_rich4_player_cards[player*15 + slot]`（0x499120，共 60 字节）。0 表示空槽，1–30 为卡片 ID。NPC 没有手牌。
- 全局库存 `_rich4_remain_card_amount[30]`（0x499198），无符号字节。存档包含两者。`asm/rich4_save_files.asm:198-210`
- 卡槽保持插入顺序，不排序；同一 ID 可重复持有。

| 原版函数 | 地址 | 规则 |
|---|---|---|
| `_rich4_player_card_num` | 0x441262 | 数 15 槽中非零个数。`asm/rich4_card_utils.asm:58-81` |
| `_rich4_find_player_cheapest_card` | 0x44128f | 按槽顺序找**价格最低**的卡；价格相同保留**最先出现**的（严格小于才替换）。初始比较值 10000。`asm/rich4_card_utils.asm:83-123` |
| `_rich4_receive_card(p, id)` | 0x4412e4 | 若已满 15 张，**先丢掉最便宜的一张**（归还库存），然后放进第一个空槽，库存 −1。**不检查库存是否为 0**（库存检查由调用方做）。`asm/rich4_card_utils.asm:125-167` |
| `_rich4_consume_card(p, id)` | 0x441343 | 删除第一个等于 id 的槽，后面的槽前移，末槽清零，库存 +1；找不到则什么都不做。`asm/rich4_card_utils.asm:169-218` |
| `_rich4_player_has_card(p, id)` | 0x4413ad | 是否持有。`asm/rich4_card_utils.asm:220-253` |

要点：
- **手牌上限 15**。满手时获得新卡会自动丢弃最便宜的卡——即使新卡更便宜，或丢掉的是同 ID 的卡。
- 卡片被“使用”即归还全局库存（`consume` 时 +1），之后可再次从商店/事件中出现。
- 库存字节溢出按 8 位环绕（原版无保护），重制可直接用 `Uint8Array` 复现或加断言。

### 2.2 人类玩家使用卡片【代码确认】

入口 `_rich4_ui_use_card_entry`（0x441baa），`asm/rich4_ui_use_card.asm:760-863`；由顶部面板的“卡片”按钮调用（`asm/rich4_ui_clicking_top_panel.asm:92`）。

1. 打开卡片面板（15 格，5 列 × 3 行）。左键选卡，右键取消。
2. 选中后先显示该卡的特写与“使用××卡”文字（`fcn_00441f73`），**再**调用效果函数 `card_functions[id]()`。
3. 效果函数返回非 0 = 已生效（卡在效果函数内部被消耗），面板关闭。
4. 返回 0 = 条件不满足或在目标选择中取消（卡不消耗），播放错误音效后**重新打开面板**。
5. 在面板上直接右键取消 → 关闭面板，不使用。
6. 被动卡（18–21）的效果函数是 `fcn_004420d5`（恒返回 0），所以在面板中点它们只会报错重来。

一次打开面板最多成功使用一张卡。面板能否在同一回合再次打开、是否只能在掷骰前打开，取决于顶部面板的可用状态（不属于卡片模块）。【推测·待实测】见 Q1。

### 2.3 电脑（及托管）玩家使用卡片【代码确认】

- 每回合掷骰前的电脑流程：先执行出售界面逻辑（`_rich4_ui_sale_entry`），然后 `rand() & 1`：奇数 → 尝试用卡（`_rich4_ui_use_card_entry`），偶数 → 尝试用道具。`asm/rich4.asm:11637-11645`（0x418e13 附近）。**因此电脑每回合只有 50% 机会进入用卡流程，且最多用一张卡。**
- 进入条件：`who_plays & 6`（电脑或托管）且玩家设置字节 `+0x16` 的 bit0 为 1（“允许用卡”）。`asm/rich4_ui_use_card.asm:865-877`
- 选卡窗口：持卡数 `n`；若 `n ≤ 8` 从槽 0 开始取 8 个槽；若 `n > 8`，起点 `s = rand() % n`，按槽号循环取 8 张。`asm/rich4_ui_use_card.asm:878-922`
- 按顺序逐张调用 `fcn_0041e69e(id)`（AI 判定）；遇到空槽（0）立即结束；**第一张返回 1 的卡**显示特写后执行效果函数，然后结束（不管效果函数成功与否）。`asm/rich4_ui_use_card.asm:924-962`
- AI 判定的门槛与每张卡的判定条件见第 6 节。效果函数通过 `_rich4_get_ai_card_param_value(i)`（读 0x48be58 起的数组）取得 AI 预先算好的目标，而不是走鼠标选择器。

### 2.4 目标选择器（人类）【代码确认】

`_rich4_select_instance_with_mouse(flags)`（0x446ae8）→ 回调 `_rich4_select_instance_callback`（0x445e4d），`asm/rich4_ui_use_tool.asm:290-900`。

**点选方式**：选择器在 440×440 的地图画面里按鼠标位置查“实例缓冲区” `ref_00474938`（`_rich4_get_instance_from_position`，`asm/rich4.asm:3968`）。缓冲区由 `fcn_00409b18`（`asm/rich4.asm:2829-3050`）按画面上**实际画出的东西**逐像素写入实例号：

| 实例号 | 画出的东西 | 出处 |
|---|---|---|
| 1–1999 | 路面节点（节点形状） | `rich4.asm:2880-2925` |
| 2001–3999 / 4001–5999 / 6001– | 小地块 / 设施 / 企业的地皮与建筑形状（点的是**建筑/地皮**，不是路面节点） | `rich4.asm:2930-3000` |
| `0x8000 \| (1<<p)` | 正式玩家 p 的人物精灵；只画“在地图上（x≠0）且不在饭店/消失/牢/院（+0x32 双字为 0）”的玩家 | `rich4.asm:1303-1311`、`:1406-1413` |
| `0x8000 \| (0x10<<i)` | 特殊角色 i = 0–3（小偷、强盗、流氓、间谍）；i = 4（机器娃娃）实例号为 0，**点不到** | `rich4.asm:1550-1568` |
| `0x8000 \| ((对象号)<<8)` | 路面上的对象（神明、路障、地雷、定时炸弹…） | `rich4.asm:1828-1889` |
| `0xC000 \| ((对象号)<<8)` | **挂在玩家身上的定时炸弹**（附身对象画在玩家旁边；类型 0x12 额外置 0x4000 标志） | `rich4.asm:1716-1735`、`:2016-2025` |

flags 低 16 位：低字节 = 可选对象类型掩码，次字节 = 附加条件编号；高 16 位为光标外观（卡片统一 0x0e0c）。

| 类型位 | 含义 |
|---|---|
| 0x01 | 路面节点（1–1999）——只有道具用 |
| 0x02 | 小地块（2001–3999） |
| 0x04 | 大型地块（4001–5999） |
| 0x10 | 玩家/NPC（返回 `0x8000` 加玩家位掩码；编号 <4 的必须 who_plays ≠ 0） |
| 0x20 | 地图对象（神明、路障等，返回 `0x8000` 加 `对象号<<8`） |
| 0x08 | 禁止右键取消 |
| 0x40 | 等价于 0x37 全部 |
| 0x80 | 鼠标到画面边缘时**卷动地图**（`rich4_ui_use_tool.asm:464-566`）；没有此位就只能点当前画面里的东西 |

| 条件号 | 规则（`ref_00445e2d` 跳转表，`rich4_ui_use_tool.asm:290-298`，各条件 `:666-850`） |
|---|---|
| 0 | 无附加条件 |
| 1 | 自己的地（设施还须等级≠0） |
| 2 | 与**自己脚下地块**同类（同为小地块或同为设施），且不是脚下那块 |
| 3 | 表项直接跳到“拒绝”（任何东西都不能选；没有卡片使用） |
| 4 | 正式玩家（编号 0–3）且不是自己 |
| 5 | 地块：不是自己的且等级≠0 |
| 6 | 同 5；或对象类型为 16 路障 / 17 地雷 / 18 定时炸弹（对象号取 `实例号 & 0x7f00`，**不去掉 0x4000 标志**，见下） |
| 7 | 不是自己（NPC 可选） |
| 8 | 无主且等级为 0 的空地 |

卡片的 flags 都**没有 0x80**：卡片目标只能在使用者当前的地图画面（以使用者为中心的 440×440）里点选，不能卷动。道具里只有飞弹 0x300c0、核子飞弹 0x400c0 带 0x80（全图）。

### 2.5 状态计数器的推进（停留/乌龟/冬眠/梦游/同盟）【代码确认】

`fcn_0041c84f(player)` 在**轮到该玩家时、行动之前**调用（`current_player` 已切换），`asm/rich4.asm:11795-11829`、`asm/rich4_player_core_actions.asm:4101-4470`。处理顺序：

1. 饭店/消失/坐牢/住院计数（各自规则，略）。
2. 若该玩家不在饭店/消失/牢/院（`+0x32..+0x35` 四字节全 0）：
   - 冬眠 `+0x36` 带 0x80 → 清零（醒来，恢复动画）。
   - 梦游 `+0x37` 带 0x80 → 清零，并恢复梦游前的交通方式和骰子数（前提是道具栏里还有那辆机车/汽车，恢复时从道具栏扣回；没有则步行 1 骰）。
   - 乌龟 `+0x39` 带 0x80 → 清零。
3. 停留 `+0x38`、`+0x3b`、`+0x3c` 带 0x80 → 清零。同盟 `+0x3d` 带 0x80 → `_rich4_end_ally`。
4. 若不在饭店/消失/牢/院：冬眠、梦游、乌龟各自非零则 −1，减到 0 时写 0x80。
5. 停留（无论是否在牢里）非零则 −1，减到 0 写 0x80。
6. 同盟天数非零：本玩家与盟友**双向**敌意各 −20×pi，然后天数 −1，减到 0 写 0x80。
7. 附身神明剩余天数 −1，到 0 → 神明离开。

“计数器非零”即处于该状态（0x80 也算），所以：**写入 N 的状态从下一次轮到该玩家开始，共持续 N 个回合**；对**自己**使用时卡片会写入 N−1 或 0x80，使“本回合”也算一回合，总回合数保持一致：

| 卡 | 对他人写入 | 对自己写入 | 实际效果回合数 |
|---|---|---|---|
| 停留 14 | 1 | 0x80 | 1（自己用：本回合不走） |
| 乌龟 30 | 3 | 2 | 3 |
| 梦游 16 | 5 | 4 | 5 |
| 冬眠 15 | 5（不会作用于自己） | — | 5 |
| 同盟 29 | 双方各 7 | — | 约 7–8 个各自回合（先到 0x80 的一方结束双方，见 Q7） |

行走的影响：停留计数非零 → 本回合不掷骰不移动；乌龟计数非零 → 不掷骰，剩余步数固定为 1。`asm/rich4_player_utils.asm:1013-1029`（fcn_0040dd1f，0x40dd53）。冬眠与梦游对行动的具体影响（不移动/随机走）属于移动模块，此处只确认：**冬眠或梦游中的地主不能收过路费**（见 §3.29 的过路费判定）。

**嫁祸卡选人**：
- 人类持有者：候选 = 所有仍在游戏中的其他玩家（**包括施害者本人**，不限是否在牢/院）。只有一名候选 → 是/否对话框，选“否”则不使用；多名 → 列表选择（`fcn_00440e1a`，返回值直接作为新承受者；列表是否带“不使用”选项【推测·待实测】Q26）。
- 电脑持有者：目标 = 敌意值最高的玩家（`hostility[p][j]` 严格最大且 >0，平手取编号小者）；若全为 0 → 从“仍在游戏且不在饭店/消失/牢/院”的其他玩家中 `rand() % k` 随机挑一个；仍无 → 不使用。`asm/rich4_player_utils.asm:105-165`
- 电脑是否使用由 mode 决定：
  - mode 0（惩罚类：梦游、陷害、命运/新闻/魔法屋的坏事）→ 总是使用。
  - mode 1（过路费类，amount=费用）→ `fee > 现金` 或 `(rand() % 4000 + 4000) × pi < fee` 时使用。
  - mode 2（查税）→ `现金 × 0.2 > 4000 × pi` 时使用（浮点比较）。
  - 其他 → 不使用。
- 使用后：消耗卡 19，双方台词。

**免费卡**：
- 人类：弹出是/否询问。电脑：`fee > 现金` 或 `(rand() % 3000 + 3000) × pi < fee` 时使用。
- 只在以下调用点被询问（均要求持有 20）：
  1. 小地块过路费（`asm/rich4_player_core_actions.asm:790-858`）；
  2. 大型设施费用（`…:1410-1485`，设施类型为 1 时**跳过**免费卡判定）；
  3. 第三处费用（`…:2160-2215`，收款方传 −1，推测为非玩家设施/企业，见 Q12）；
  4. 查税卡（§3.26）。
- 过路费三处的共同顺序：
  1. 若 `费用 ≥ 2000×pi` 或 `费用 > 现金+存款`，且持有免费卡 → 询问/判定免费卡，用了则费用变 0；
  2. 再判断（用新费用）同一条件，且持有嫁祸卡 → mode 1 嫁祸，换付款人；
  3. 费用非 0 时还有“死神”代付检查（神明模块）。
  - 所以低于 2000×pi 且付得起的费用**不会**触发免费卡/嫁祸卡。【代码确认】阈值 `pi×2000` 由 `pi*3*8+pi)*16*5` 移位运算得到。

**免罪/嫁祸的其他调用点**（mode 0）：命运 `asm/rich4_fortune.asm:795、880、1355（住院）、2306（坐牢）`，新闻 `asm/rich4_news.asm:3156（坐牢 5 天）`，魔法屋 `asm/rich4_magic_house.asm:270（坐牢 3 天）、689（住院 3 天）`。各事件的具体惩罚见命运/新闻/魔法屋文档。

## 3. 逐卡详细规则

> 格式：前置条件 → 失败时（返回 0，**不消耗**）→ 成功时的执行顺序。除特别说明外，效果函数在“确定目标之后、执行效果之前”消耗卡片；台词、动画不影响规则，从略。

### 3.1 均富卡（ID 1）【代码确认】`asm/rich4_card_junfuka.c`（0x4420d8）

- 无目标选择，无失败分支。
- 消耗卡 → `avg = trunc(Σ现金 / 人数)`，统计对象是 `who_plays ≠ 0` 的玩家（含住院、坐牢等）；**只算现金，不算存款**。
- 对每个统计对象：现金 > avg 的，先记敌意 `(现金 − avg) / 100`（整数除法）；然后所有人现金 = avg。
- 整除余数直接消失（总现金可能减少最多 人数−1 元）。
- 现金为负的玩家也参与平均（原版不特殊处理）。

### 3.2 均贫卡（ID 2）【代码确认】`asm/rich4_card_junpinka.c`（0x4421b4）

- 目标：另一名正式玩家（flags 0x0e0c0410）。取消 → 返回 0。
- 消耗卡 → `avg = trunc((自己现金 + 对方现金) / 2)`；若对方现金 > avg，敌意 `(对方现金 − avg)/100`；双方现金都设为 avg。
- 注意：如果自己更有钱，同样被拉平（卡是对称的，AI 只会在对自己有利时用，见第 6 节）。

### 3.3 购地卡（ID 3）【代码确认】`asm/rich4_card_goudika.asm`（0x442325）

- 目标：**自己脚下**的地块。
- 失败（不消耗、无提示）：脚下不是地块；地块无主；地块是自己的。
- 价格：小地块 `(地价 + 等级 × 每级建筑价) × pi`；设施 `(+0x22 地价 + 等级 × +0x24) × pi`。不受涨价状态影响。
- 价格 > 自己**现金**（不含存款）→ 提示“现金不足”，返回 0，不消耗。
- 成功顺序：
  1. 敌意：`地价 × pi × (等级 + 2) / 5`（double，受 §0.3 ABI 怪癖影响）。
  2. 地主改为自己；刷新小地图。
  3. 若开局设置了“土地期限”（0x499110 ≠ 0）：到期日 = 今天 + 期限（表 0x4751f0：2 年/1 年/6 个月/3 个月/1 个月的打包日期增量），写入 `+0x30`/`+0x34`。
  4. 转账：自己付价格给原地主（**进原地主存款**）。
  5. 消耗卡，返回 1。
- 建筑随地一起转让，建筑类型/等级不变。

### 3.4 换地卡（ID 4）【代码确认】`asm/rich4_card_huandika.asm`（0x442622）

- 前提：脚下是地块（小地块或设施）。否则返回 0。
- 选择另一块**同类**地块（不能是脚下那块）；取消 → 0。
- 交换两块地的**地主字节**（`+0x19`）。建筑、等级、到期日都留在原地块上不动。
- 没有任何“必须有一块是自己的”限制：可以交换两个对手的地，也可以把自己的地和一块无主地交换（相当于放弃+白拿）。
- 无费用、无敌意。消耗卡，返回 1。

### 3.7 改建卡（ID 7）【代码确认】`asm/rich4_card_gaijianka.asm`（0x44309b）

### 3.8 拍卖卡（ID 8）【代码确认】`asm/rich4_card_paimaika.asm`（0x443225）、`asm/rich4_ui_auction.asm:2458-3320`

- 前提：脚下是地块。**不检查地主**（无主地、自己的地也可拍卖）。不是地块 → 返回 0。
- 若有地主：敌意 `地价 × pi × (等级 + 2) / 5`（double 怪癖）。
- 调用拍卖 `_rich4_ui_auction_entry(使用者, 地块, 1)`：
  - 起拍价（小地块）：`trunc(地价 × (1 + 0.5 × 等级)) × pi`。
  - 有人得标：得标者付成交价给**卡片使用者**（`fcn_0041d2c6(winner, user, price, 0)`，进使用者存款），地主改为得标者（若开局设有土地期限，且该地原本无主，则重设到期日）。
  - 无人得标（返回 0）：地主清为 0、到期日清 0，**建筑保留**。
- 消耗卡，返回 1（不管拍卖结果）。
- 竞价规则（谁能出价、AI 出价策略）属于拍卖模块。

### 3.9 天使卡（ID 9）【代码确认】`asm/rich4_card_tianshika.asm`（0x4434c0）、`asm/rich4.asm:4534-4664`

- 目标：任意地块（0x0e0c0006）。取消 → 0。选定后立即消耗卡。
- **小地块**：遍历所有小地块（1..num_lands），与目标同一路段（地名相同）且等级 < 5 的：
  - 类型 0 → 等级 +1；
  - 类型 ≠ 0 且等级 0 → 等级设为 1（类型 ≠ 0 且已有 1 级的不变）；
  - **不检查地主**：无主地、对手的地也一起升级（无主空地会出现无主的 1 级房屋）。
  - 若有任何类型 0 的地被升到 5 级 → 播放特别动画（`fcn_0040b0cd`，纯表现）。
- **设施**：只升级目标这一块（`fcn_0040b110`）：
  - 等级 0：选择设施类型（电脑：若该设施是使用者自己的，类型 = `rand() % 4 + 1`，否则类型 0；人类：弹菜单）→ 等级 1。
  - 等级 ≥ 1：等级 < 该类型上限（[1,5,5,1,5]）时 +1。
- 无敌意、无费用。返回目标引用号（非 0）。

### 3.10 恶魔卡（ID 10）【代码确认】`asm/rich4_card_emoka.asm`（0x4436e0）

### 3.11 怪兽卡（ID 11）【代码确认】`asm/rich4_card_guaishouka.asm`（0x443917）、`asm/rich4.asm:3989-4105`（fcn_0040ab4a）

## 5. AI 用卡的总框架

### 5.1 调用链【代码确认】

1. 电脑/托管玩家回合开始（掷骰前）：出售界面逻辑 → `rand() & 1` 决定本回合尝试用卡还是用道具（各 50%）。`asm/rich4.asm:11617-11645`（loc_00418dc6）
2. 用卡：需要 `who_plays & 6` 且设置字节 `+0x16` bit0（“允许用卡”，AI 设置界面中的开关，`asm/rich4_ui_ai_settings.asm` loc_0041e0d7）。
3. 最多取 8 张卡（§2.3 的循环窗口），逐张调用 `fcn_0041e69e(id)`，**第一张通过的立即使用**，不在多张卡之间打分比较。手牌顺序（获得顺序）+ 随机起点决定优先级。

### 5.2 攻击性门槛 `fcn_0041e69e`【代码确认】`asm/rich4_ai_use_card.asm:42-74`

`d = card.f7 − player.f23`。`f23`（`+0x17`）是 AI 设置界面中的三档等级 0/1/2（`asm/rich4_ui_ai_settings.asm` loc_0041e10b/126/140；按钮的界面文字未核对，见 Q19）。

| f7 \ f23 | 0 | 1 | 2 |
|---|---|---|---|
| 0 | 判定 | 判定 | 判定 |
| 1 | 1/3 概率判定（`rand() % 3 == 0`） | 判定 | 判定 |
| 2 | 永不使用 | 1/3 概率判定 | 判定 |

通过门槛后调用逐卡判定函数（跳转表 `ref_00475328`，`asm/rich4_ai_use_card.asm:3663-3693`）。判定函数返回 1 表示使用，并把目标写进参数数组 `ref_0048be58[0]`（抢夺卡另写 `[1]` = 要抢的卡 ID）；卡片效果函数再从这里读取目标。

### 5.3 公共概念

- **H（宿敌）**：`_rich4_find_most_hostile_player(self)`，对自己敌意值严格最大且 >0 的存活对手；平手取编号小者；没有则为 −1。`asm/rich4_player_utils.asm:105-141`
- **画面内（视野）**：`fcn_0040a45c(-1)` 收集当前 440×440 地图视口里所有可点选对象，按屏幕行优先顺序。凡写“画面内”的条件都依赖当时的镜头位置。`asm/rich4.asm:3591`。重制需定义“电脑回合开始时镜头以该电脑为中心”的等价视野（Q20）。
- **路径预测**：`fcn_0040b221(p, n)` 预测 p 前方 n 个节点（≤8），遇岔路用 `rand()` 选一支并返回“有岔路”标志。`asm/rich4.asm:4666-4777`
- **愿意出钱的地** `fcn_0041e8e6(H, 地块)`：小地块——属于他人、等级≠0、且自己在同路段有地；或属于 H 且等级 ≥2（H 为 −1 时直接否）。设施——属于他人且等级≠0。`asm/rich4_ai_use_card.asm:270-377`

## 8. 重制实现要点

### 8.1 设计原则

1. **数据驱动的卡片表**：ID、价格、库存、f6、f7、类型（主动/被动）、目标规格、效果处理器名，全部放在一张常量表里；不要把价格写进效果代码。
2. **效果函数返回“是否生效”**：`false` 时不得改动任何状态（尤其是不消耗卡），面板重开，以复现原版“取消/条件不满足不吞卡”。
3. **消耗时机按原版**：多数卡在“目标确定后、效果前”消耗；购地、换地、换屋、改建、拍卖、抢夺、送神在**效果后**消耗（顺序影响满手边界与台词，§3.13）。
4. **随机数集中管理**：所有 `rand()` 走同一个可注入的 `Rng`，调用次数与顺序按本文描述（例如 AI 选卡窗口在 `n>8` 时恰好消耗一次 `rand()`）。原版会用 `GetTickCount` 重新播种（`asm/rich4_player_core_actions.asm` loc_0041d066），因此不可能逐帧重放原版随机序列；重制只需保证“0–32767 的 15 位输出 + 取模”的分布特征，LCG 常数待 Q24 核对后再决定是否复刻。
5. **怪癖开关**：`quirks.hostilityDoubleAbi`、`quirks.robToolUsesCardPrice`、`quirks.aiShopSellsBySlot`、`quirks.aiStopCardStaleParam`、`quirks.priceUpFacilityStaleScore` 默认 `true`（与原版一致），可关闭得到“设计意图”行为。
6. **计时器语义**：状态字节的 “N / 0x80” 两阶段机制可直接用 `remaining: number` + `expiring: boolean` 表达，但在回合开始处理时必须先清 `expiring` 再递减，次序同 §2.5。

- **运行**：沿用 `rich4-renew/editor/packaging/launch.sh` 的 Wine + cnc-ddraw 配置（`windowed=true`、`renderer=gdi`）运行原版 `rich4.exe` v3.11（SHA256 见 `upstream/rich4/readme.rst`）。
